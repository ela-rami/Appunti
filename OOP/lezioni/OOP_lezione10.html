1. Cosa sono i Design Pattern Comportamentali?

I Design Pattern Comportamentali si concentrano sugli algoritmi e sull'assegnazione delle responsabilità tra gli oggetti. A differenza dei pattern creazionali (che astraggono il processo di istanziazione) e strutturali (che descrivono come assemblare oggetti), i pattern comportamentali descrivono come gli oggetti comunicano e collaborano tra loro.

L'obiettivo principale è aumentare la flessibilità della comunicazione tra oggetti e incapsulare comportamenti che variano, rendendoli intercambiabili.

2. Observer Pattern

L'Observer è un pattern che definisce una dipendenza uno-a-molti tra oggetti, in modo che quando un oggetto (il "soggetto") cambia stato, tutti i suoi dipendenti (gli "osservatori") vengano notificati e aggiornati automaticamente.

Questo pattern è fondamentale per creare sistemi event-driven e per disaccoppiare gli oggetti che producono dati da quelli che li consumano.

Struttura

                        classDiagram
                            direction LR
                            class Subject {
                                <>
                                +registerObserver(Observer)
                                +unregisterObserver(Observer)
                                +notifyObservers()
                            }
                            class Observer {
                                <>
                                +update(data)
                            }
                            class ConcreteSubject {
                                -observers: List~Observer~
                                -state
                                +getState()
                                +setState(newState)
                            }
                            class ConcreteObserver {
                                -subject: Subject
                                +update(data)
                            }
                            
                            ConcreteSubject --|> Subject
                            ConcreteObserver --|> Observer
                            Subject o-- "many" Observer : observers
                            ConcreteObserver ..> ConcreteSubject : knows
  • Subject (Soggetto): L'interfaccia o la classe astratta che definisce i metodi per aggiungere, rimuovere e notificare gli osservatori. Mantiene una lista dei suoi osservatori.
  • Observer (Osservatore): L'interfaccia che tutti gli osservatori concreti devono implementare. Di solito ha un solo metodo, `update()`, che viene chiamato dal soggetto.
  • ConcreteSubject: Implementa l'interfaccia `Subject`. Mantiene lo stato di interesse e notifica i suoi osservatori quando questo stato cambia.
  • ConcreteObserver: Implementa l'interfaccia `Observer` e reagisce alla notifica, aggiornando il proprio stato o eseguendo un'azione in base ai dati ricevuti dal soggetto.

2.1. Esempio: Agenzia di Stampa

Un'agenzia di stampa (il `Subject`) pubblica notizie. Diversi canali di informazione (gli `Observer`, come TV, radio, giornali online) sono interessati a ricevere queste notizie non appena vengono pubblicate.


// 1. L'interfaccia Observer
public interface Channel {
    void update(String news);
}

// 2. I ConcreteObserver
public class NewsChannel implements Channel {
    private String channelName;
    public NewsChannel(String name) { this.channelName = name; }
    
    @Override
    public void update(String news) {
        System.out.println(channelName + " ha ricevuto la notizia: '" + news + "'");
    }
}

// 3. Il (Concrete)Subject
// In Java, esiste già una classe `Observable` e un'interfaccia `Observer` (ora deprecate).
// Qui creiamo la nostra implementazione per chiarezza.
import java.util.ArrayList;
import java.util.List;

public class NewsAgency {
    private String news;
    private List channels = new ArrayList<>();

    public void addObserver(Channel channel) {
        channels.add(channel);
    }

    public void removeObserver(Channel channel) {
        channels.remove(channel);
    }

    public void setNews(String news) {
        this.news = news;
        // Quando lo stato cambia, notifica tutti gli osservatori registrati
        notifyObservers();
    }

    private void notifyObservers() {
        for (Channel channel : this.channels) {
            channel.update(this.news);
        }
    }
}

// 4. Il Client
public class Main {
    public static void main(String[] args) {
        NewsAgency ansa = new NewsAgency();
        
        Channel raiNews = new NewsChannel("Rai News 24");
        Channel skyTg24 = new NewsChannel("Sky TG24");
        
        // I canali si registrano all'agenzia
        ansa.addObserver(raiNews);
        ansa.addObserver(skyTg24);
        
        // L'agenzia pubblica una notizia. I canali vengono notificati automaticamente.
        ansa.setNews("L'Italia vince i mondiali di programmazione!");
        
        // Output:
        // Rai News 24 ha ricevuto la notizia: 'L'Italia vince i mondiali di programmazione!'
        // Sky TG24 ha ricevuto la notizia: 'L'Italia vince i mondiali di programmazione!'
    }
}

3. Strategy Pattern

Il Strategy Pattern è un pattern comportamentale che permette di definire una famiglia di algoritmi, incapsulare ciascuno di essi in una classe separata e renderli intercambiabili. Questo pattern permette all'algoritmo di variare indipendentemente dai client che lo utilizzano.

È una delle applicazioni più potenti del principio Open/Closed: puoi aggiungere nuove strategie senza modificare il contesto che le utilizza.

Struttura

                        classDiagram
                            direction LR
                            class Context {
                                -strategy: Strategy
                                +setStrategy(Strategy)
                                +executeStrategy()
                            }
                            class Strategy {
                                <>
                                +doAlgorithm(data)
                            }
                            class ConcreteStrategyA {
                                +doAlgorithm(data)
                            }
                            class ConcreteStrategyB {
                                +doAlgorithm(data)
                            }
                            
                            Context o-- Strategy
                            ConcreteStrategyA --|> Strategy
                            ConcreteStrategyB --|> Strategy
  • Strategy: Un'interfaccia comune a tutte le strategie supportate. Definisce il metodo che l'algoritmo deve eseguire.
  • ConcreteStrategy: Le classi che implementano l'interfaccia `Strategy`, fornendo la logica concreta di un algoritmo specifico.
  • Context: La classe che utilizza una strategia. Mantiene un riferimento a un oggetto `Strategy` e comunica con esso solo attraverso la sua interfaccia. Può avere un metodo per cambiare la strategia a runtime.

3.1. Esempio: Strategie di Pagamento

Un carrello della spesa online (`Context`) deve permettere a un utente di pagare usando diversi metodi (strategie), come carta di credito o PayPal.


// 1. L'interfaccia Strategy
public interface MetodoPagamento {
    void paga(double importo);
}

// 2. Le ConcreteStrategy
public class CartaDiCredito implements MetodoPagamento {
    private String nome;
    private String numeroCarta;

    public CartaDiCredito(String nome, String numero) {
        this.nome = nome;
        this.numeroCarta = numero;
    }

    @Override
    public void paga(double importo) {
        System.out.println("Pagati €" + importo + " con Carta di Credito.");
    }
}

public class PayPal implements MetodoPagamento {
    private String email;

    public PayPal(String email) {
        this.email = email;
    }

    @Override
    public void paga(double importo) {
        System.out.println("Pagati €" + importo + " con PayPal (account: " + email + ").");
    }
}

// 3. Il Context
public class CarrelloSpesa {
    private List items = new ArrayList<>();
    
    public void aggiungiItem(Item item) { this.items.add(item); }
    public double calcolaTotale() {
        return items.stream().mapToDouble(Item::getPrezzo).sum();
    }
    
    // Il carrello esegue il pagamento usando la strategia fornita
    public void paga(MetodoPagamento metodo) {
        double importo = calcolaTotale();
        metodo.paga(importo);
    }
}

// 4. Il Client
public class Main {
    public static void main(String[] args) {
        CarrelloSpesa carrello = new CarrelloSpesa();
        carrello.aggiungiItem(new Item("Libro OOP", 45.0));
        carrello.aggiungiItem(new Item("Tazza", 10.0));

        // L'utente decide di pagare con carta di credito
        MetodoPagamento carta = new CartaDiCredito("Mario Rossi", "1234-5678-9012-3456");
        carrello.paga(carta);

        // L'utente decide di pagare con PayPal
        MetodoPagamento paypal = new PayPal("mario.rossi@email.com");
        carrello.paga(paypal);

        // Output:
        // Pagati €55.0 con Carta di Credito.
        // Pagati €55.0 con PayPal (account: mario.rossi@email.com).
    }
    // Classe di supporto Item
    static class Item {
        private String nome; private double prezzo;
        public Item(String nome, double prezzo){this.nome=nome; this.prezzo=prezzo;}
        public double getPrezzo(){return prezzo;}
    }
}
💡 Strategy e Interfacce Funzionali
In Java 8+, se l'interfaccia `Strategy` è funzionale (ha un solo metodo astratto), si possono usare le Lambda Expressions per definire le strategie al volo, rendendo il codice ancora più conciso.
