1. Cosa sono i Design Pattern Strutturali?

I Design Pattern Strutturali si concentrano su come classi e oggetti possono essere composti per formare strutture più grandi e complesse. Mentre i pattern creazionali si occupano dell'istanziazione, quelli strutturali si occupano delle relazioni tra entità.

L'obiettivo principale è garantire che, se una parte del sistema cambia, il resto del sistema non debba cambiare. Questi pattern aiutano a definire relazioni pulite e stabili, spesso sfruttando l'ereditarietà e la composizione in modi intelligenti per aumentare la flessibilità.

2. Decorator Pattern

Il Decorator permette di aggiungere nuove funzionalità a un oggetto in modo dinamico, a runtime, senza alterare la sua classe. Questo pattern è un'alternativa flessibile all'ereditarietà per estendere il comportamento.

Funziona "avvolgendo" (wrapping) l'oggetto originale in uno o più oggetti "decoratori" che condividono la stessa interfaccia.

Struttura

                        classDiagram
                            direction TB
                            class Component {
                                <>
                                +operation()
                            }
                            class ConcreteComponent {
                                +operation()
                            }
                            class Decorator {
                                <>
                                -component: Component
                                +operation()
                            }
                            class ConcreteDecoratorA {
                                +operation()
                            }
                            class ConcreteDecoratorB {
                                +operation()
                            }
                            
                            ConcreteComponent --|> Component
                            Decorator --|> Component
                            Decorator o-- Component
                            ConcreteDecoratorA --|> Decorator
                            ConcreteDecoratorB --|> Decorator
  • Component: L'interfaccia comune sia per gli oggetti da decorare che per i decoratori.
  • ConcreteComponent: L'oggetto base a cui vogliamo aggiungere funzionalità.
  • Decorator: Una classe astratta che implementa l'interfaccia `Component` e contiene un riferimento (composizione) a un altro oggetto `Component`. La sua implementazione di `operation()` delega semplicemente la chiamata all'oggetto avvolto.
  • ConcreteDecorator: Estende il `Decorator` e aggiunge il suo comportamento specifico, prima o dopo aver delegato la chiamata all'oggetto avvolto.

2.1. Esempio: Personalizzare un Caffè

Immaginiamo di dover calcolare il costo di un caffè con vari ingredienti aggiuntivi (latte, panna, cioccolato). Usare l'ereditarietà creerebbe un'esplosione di classi (`CaffeConLatte`, `CaffeConPanna`, `CaffeConLatteEPanna`, ...). Il Decorator risolve elegantemente il problema.


// 1. L'interfaccia Component
public interface Caffe {
    double getCosto();
    String getIngredienti();
}

// 2. Il ConcreteComponent
public class CaffeSemplice implements Caffe {
    @Override
    public double getCosto() { return 1.0; }
    @Override
    public String getIngredienti() { return "Caffè"; }
}

// 3. Il Decorator astratto
public abstract class CaffeDecorator implements Caffe {
    protected final Caffe caffeDecorato;

    public CaffeDecorator(Caffe caffe) {
        this.caffeDecorato = caffe;
    }

    // Delega all'oggetto avvolto
    @Override
    public double getCosto() { return caffeDecorato.getCosto(); }
    @Override
    public String getIngredienti() { return caffeDecorato.getIngredienti(); }
}

// 4. I ConcreteDecorator
public class ConLatte extends CaffeDecorator {
    public ConLatte(Caffe caffe) { super(caffe); }

    @Override
    public double getCosto() {
        return super.getCosto() + 0.5; // Aggiunge il costo del latte
    }
    @Override
    public String getIngredienti() {
        return super.getIngredienti() + ", Latte"; // Aggiunge l'ingrediente
    }
}

public class ConPanna extends CaffeDecorator {
    public ConPanna(Caffe caffe) { super(caffe); }
    
    @Override
    public double getCosto() { return super.getCosto() + 0.7; }
    @Override
    public String getIngredienti() { return super.getIngredienti() + ", Panna"; }
}

// 5. Il Client
public class Main {
    public static void main(String[] args) {
        Caffe mioCaffe = new CaffeSemplice();
        System.out.println(mioCaffe.getIngredienti() + ": €" + mioCaffe.getCosto());

        // Aggiungo il latte decorando l'oggetto base
        mioCaffe = new ConLatte(mioCaffe);
        System.out.println(mioCaffe.getIngredienti() + ": €" + mioCaffe.getCosto());

        // Aggiungo la panna decorando l'oggetto già decorato con il latte
        mioCaffe = new ConPanna(mioCaffe);
        System.out.println(mioCaffe.getIngredienti() + ": €" + mioCaffe.getCosto());
        // Output:
        // Caffè: €1.0
        // Caffè, Latte: €1.5
        // Caffè, Latte, Panna: €2.2
    }
}

3. Composite Pattern

Il Composite permette di comporre oggetti in strutture ad albero per rappresentare gerarchie parte-tutto. Il punto chiave è che permette ai client di trattare oggetti individuali (foglie) e composizioni di oggetti (nodi compositi) in modo uniforme.

Ad esempio, in un sistema grafico, un `Gruppo` di forme può essere trattato esattamente come una `Forma` singola: entrambi possono essere disegnati, spostati, ridimensionati.

Struttura

                        classDiagram
                            direction TB
                            class Component {
                                <>
                                +operation()
                            }
                            class Leaf {
                                +operation()
                            }
                            class Composite {
                                -children: List~Component~
                                +operation()
                                +add(Component)
                                +remove(Component)
                            }
                            
                            Leaf --|> Component
                            Composite --|> Component
                            Composite o-- "many" Component
  • Component: L'interfaccia comune che dichiara le operazioni sia per gli oggetti semplici (foglie) che per quelli complessi (compositi).
  • Leaf (Foglia): Rappresenta un oggetto primitivo nella gerarchia. Non ha figli e implementa le operazioni direttamente.
  • Composite (Composito): Rappresenta un oggetto che può avere figli (altri `Component`, che possono essere a loro volta foglie o altri compositi). La sua implementazione di `operation()` tipicamente itera sui suoi figli e delega a loro la chiamata.

3.1. Esempio: Sistema di File Grafico

Vogliamo calcolare la dimensione totale di un sistema di file, dove sia i singoli file che le cartelle devono rispondere a un metodo `getSize()`.


// 1. L'interfaccia Component
public interface FileSystemComponent {
    int getSize(); // Dimensione in KB
}

// 2. La classe Leaf
public class File implements FileSystemComponent {
    private String name;
    private int size;
    public File(String name, int size) { this.name = name; this.size = size; }
    
    @Override
    public int getSize() { return this.size; }
}

// 3. La classe Composite
public class Directory implements FileSystemComponent {
    private String name;
    private List children = new ArrayList<>();
    public Directory(String name) { this.name = name; }
    
    public void add(FileSystemComponent component) { children.add(component); }
    public void remove(FileSystemComponent component) { children.remove(component); }

    @Override
    public int getSize() {
        int totalSize = 0;
        // Delega la chiamata a tutti i figli e somma i risultati
        for (FileSystemComponent child : children) {
            totalSize += child.getSize();
        }
        return totalSize;
    }
}

// 4. Il Client
public class Main {
    public static void main(String[] args) {
        Directory root = new Directory("root");
        Directory documents = new Directory("documenti");
        Directory pictures = new Directory("immagini");
        
        File doc1 = new File("tesi.docx", 1024);
        File pic1 = new File("vacanza.jpg", 2048);
        File pic2 = new File("gatto.png", 512);

        root.add(documents);
        root.add(pictures);
        documents.add(doc1);
        pictures.add(pic1);
        pictures.add(pic2);

        // Il client tratta tutto in modo uniforme, senza sapere se è un file o una cartella.
        System.out.println("Dimensione documenti: " + documents.getSize() + " KB"); // 1024
        System.out.println("Dimensione immagini: " + pictures.getSize() + " KB");   // 2560
        System.out.println("Dimensione totale root: " + root.getSize() + " KB");     // 3584
    }
}

4. Bridge Pattern

Il Bridge è un pattern che serve a disaccoppiare un'astrazione dalla sua implementazione, in modo che le due possano evolvere indipendentemente. È particolarmente utile quando si ha una gerarchia di astrazioni e una gerarchia di implementazioni, per evitare di dover creare una classe per ogni combinazione possibile (esplosione di classi N x M).

Struttura

                        classDiagram
                            direction LR
                            class Abstraction {
                                -implementor: Implementor
                                +operation()
                            }
                            class RefinedAbstraction {
                                +refinedOperation()
                            }
                            class Implementor {
                                <>
                                +operationImpl()
                            }
                            class ConcreteImplementorA {
                                +operationImpl()
                            }
                            class ConcreteImplementorB {
                                +operationImpl()
                            }

                            Abstraction o-- Implementor
                            RefinedAbstraction --|> Abstraction
                            ConcreteImplementorA --|> Implementor
                            ConcreteImplementorB --|> Implementor
  • Abstraction: Definisce l'interfaccia di alto livello per i client. Mantiene un riferimento a un oggetto di tipo `Implementor`.
  • RefinedAbstraction: Estende `Abstraction` per aggiungere o modificare il comportamento di alto livello.
  • Implementor: Definisce l'interfaccia per le classi di implementazione. Non deve necessariamente corrispondere all'interfaccia di `Abstraction`.
  • ConcreteImplementor: Le classi che implementano l'interfaccia `Implementor` e forniscono la logica concreta di basso livello.

4.1. Esempio: Telecomandi e Dispositivi

Vogliamo avere diversi tipi di telecomandi (base, avanzato con mute) che possono controllare diversi tipi di dispositivi (TV, Radio). Senza Bridge, dovremmo creare `TvRemote`, `RadioRemote`, `AdvancedTvRemote`, `AdvancedRadioRemote`, ecc. Con il Bridge, disaccoppiamo l'astrazione "Telecomando" dall'implementazione "Dispositivo".


// 1. L'interfaccia Implementor
public interface Device {
    boolean isEnabled();
    void enable();
    void disable();
    int getVolume();
    void setVolume(int percent);
}

// 2. I ConcreteImplementor
public class Tv implements Device { /* ... implementazione per la TV ... */ }
public class Radio implements Device { /* ... implementazione per la Radio ... */ }

// 3. L'Abstraction
public class RemoteControl {
    protected Device device; // Contiene un riferimento all'implementazione

    public RemoteControl(Device device) { this.device = device; }

    public void togglePower() {
        if (device.isEnabled()) device.disable();
        else device.enable();
    }
    public void volumeUp() { device.setVolume(device.getVolume() + 10); }
    public void volumeDown() { device.setVolume(device.getVolume() - 10); }
}

// 4. La RefinedAbstraction
public class AdvancedRemoteControl extends RemoteControl {
    public AdvancedRemoteControl(Device device) { super(device); }

    public void mute() { // Funzionalità aggiuntiva
        device.setVolume(0);
    }
}

// 5. Il Client
public class Main {
    public static void main(String[] args) {
        Tv tv = new Tv();
        RemoteControl remote = new RemoteControl(tv);
        remote.togglePower();

        Radio radio = new Radio();
        // Stessa astrazione (RemoteControl), ma con un'implementazione diversa!
        AdvancedRemoteControl advancedRemote = new AdvancedRemoteControl(radio);
        advancedRemote.volumeUp();
        advancedRemote.mute();
    }
}
💡 Vantaggio del Bridge
La gerarchia dei Telecomandi (`RemoteControl`, `AdvancedRemoteControl`) può evolvere indipendentemente dalla gerarchia dei Dispositivi (`Tv`, `Radio`, `Stereo`, ...). Possiamo aggiungere un nuovo dispositivo senza toccare i telecomandi, e viceversa. Questo evita l'esplosione combinatoria delle classi.
