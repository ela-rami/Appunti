1. Perché Esistono i Generics?

Prima di Java 5, le collezioni come `ArrayList` potevano contenere solo oggetti di tipo `Object`. Questo creava due problemi principali:

  1. Necessità di Cast Espliciti: Per recuperare un oggetto dalla collezione, era necessario effettuare un cast esplicito al suo tipo originale, rendendo il codice verboso e meno leggibile.
  2. Mancanza di Type Safety: Il compilatore non poteva garantire che il cast fosse corretto. Se per errore si inseriva un oggetto di tipo diverso nella collezione, si otteneva una `ClassCastException` a runtime, un bug difficile da prevedere.
⚠️ Il Codice "Pre-Generics" (Pericoloso)

// Codice come si scriveva in Java 1.4
List list = new ArrayList();
list.add("hello");
list.add(123); // Nessun errore di compilazione!

// Questo cast funziona
String s = (String) list.get(0); 

// Questo cast fallirà a RUNTIME con una ClassCastException
Integer i = (Integer) list.get(0); // Errore logico
String s2 = (String) list.get(1); // ERRORE A RUNTIME!

I **Generics** (o tipi generici) sono stati introdotti per risolvere esattamente questi problemi, spostando il controllo dei tipi dalla fase di esecuzione alla fase di compilazione.

💡 Vantaggi dei Generics
  • Stronger Type Checking: Il compilatore verifica che nella collezione vengano inseriti solo oggetti del tipo corretto.
  • Eliminazione dei Cast: Non sono più necessari cast espliciti, rendendo il codice più pulito e sicuro.
  • Riutilizzo del Codice: Permettono di scrivere algoritmi e strutture dati generiche che funzionano con qualsiasi tipo di dato in modo sicuro.

// Codice moderno con i Generics
List list = new ArrayList<>(); // Definisco che la lista conterrà SOLO String
list.add("hello");
// list.add(123); // ERRORE DI COMPILAZIONE! Il compilatore ci protegge.

String s = list.get(0); // Nessun cast necessario.

2. Classi e Metodi Generici

Possiamo creare non solo collezioni generiche, ma anche le nostre classi, interfacce e metodi generici.

Classi e Interfacce Generiche

Si definisce un "parametro di tipo" (solitamente una lettera maiuscola come `T` per Type, `E` per Element, `K` per Key, `V` per Value) tra parentesi angolari dopo il nome della classe.


// Un'interfaccia generica per una coppia di valori
public interface Pair {
    K getKey();
    V getValue();
}

// Una classe concreta che implementa l'interfaccia generica
public class OrderedPair implements Pair {
    private K key;
    private V value;

    public OrderedPair(K key, V value) {
        this.key = key;
        this.value = value;
    }

    public K getKey() { return key; }
    public V getValue() { return value; }
}

// Utilizzo:
Pair p1 = new OrderedPair<>("Punteggio", 100);
Pair p2 = new OrderedPair<>(1, "Primo posto");

Metodi Generici

Un metodo può avere i suoi parametri di tipo, indipendenti da quelli della classe. La dichiarazione del parametro di tipo avviene prima del tipo di ritorno del metodo.


public class Util {
    // Questo metodo generico può confrontare qualsiasi tipo di Pair
    public static  boolean compare(Pair p1, Pair p2) {
        return p1.getKey().equals(p2.getKey()) &&
               p1.getValue().equals(p2.getValue());
    }
}

3. Type Erasure: Il "Trucco" dei Generics

Una domanda comune è: come funzionano i generics a runtime? La risposta è attraverso un meccanismo chiamato Type Erasure (cancellazione del tipo).

Durante la compilazione, il compilatore Java:

  1. Verifica la correttezza dei tipi: Si assicura che tutte le operazioni siano type-safe.
  2. Rimuove tutte le informazioni sui tipi generici: Sostituisce i parametri di tipo (`T`, `K`, `V`, ecc.) con il loro "bound" (limite), che per default è `Object`.
  3. Inserisce i cast necessari: Aggiunge automaticamente i cast dove serve per garantire la compatibilità con il codice non generico.
💡 Conseguenze della Type Erasure
  • Nessun overhead a runtime: La JVM non sa nulla dei generics, quindi non c'è alcun calo di performance.
  • Compatibilità all'indietro: Il codice generico può interagire con codice legacy non generico.
  • Limitazioni: Non è possibile ottenere il tipo generico a runtime (es. non si può fare `if (list instanceof List)`).

4. Tipi Generici Vincolati (Bounded Types)

A volte vogliamo limitare i tipi che possono essere usati come parametri in un tipo generico. Ad esempio, potremmo voler creare un metodo che calcola il massimo in una collezione, ma questo ha senso solo se gli elementi sono confrontabili tra loro.

Questo si ottiene con i bounded type parameters (tipi generici vincolati), usando la parola chiave `extends`.


// T deve essere un sottotipo di Number
public class Stats {
    private T[] nums;
    
    public Stats(T[] o) { this.nums = o; }
    
    public double average() {
        double sum = 0.0;
        for (T num : nums) {
            sum += num.doubleValue(); // POSSIBILE perché sappiamo che T è un Number
        }
        return sum / nums.length;
    }
}

// Utilizzo:
Integer[] i_nums = {1, 2, 3, 4, 5};
Stats intStats = new Stats<>(i_nums); // OK
System.out.println("Media: " + intStats.average());

// String[] s_nums = {"a", "b", "c"};
// Stats stringStats = new Stats<>(s_nums); // ERRORE DI COMPILAZIONE! String non estende Number.
💡 `extends` per Classi e Interfacce
Nei bounded types, si usa sempre `extends`, sia per estendere una classe che per implementare un'interfaccia. Ad esempio: `>`.

5. Sottotipi e Generics: Una Relazione Complessa

Questo è uno dei concetti più controintuitivi dei generics. Anche se `Integer` è un sottotipo di `Number`, una `List` **NON è** un sottotipo di `List`.


// Questo codice NON COMPILA
List numbers = new ArrayList();
⚠️ Perché questa regola esiste?

Per garantire la type safety. Se l'assegnazione fosse permessa, potrebbe accadere questo:


List integers = new ArrayList<>();
List numbers = integers; // Immaginiamo che sia permesso
numbers.add(3.14); // Aggiungo un Double a una lista che dovrebbe contenere solo Integer!

Integer myInt = integers.get(0); // ERRORE a runtime! Tentativo di castare un Double a Integer.

Per prevenire questo tipo di errore a runtime, il compilatore lo impedisce a compile-time. Si dice che i generics sono **invarianti** rispetto al loro parametro di tipo.

6. I Wildcards (`?`)

Come possiamo allora scrivere metodi flessibili che accettino collezioni di tipi diversi ma correlati? La soluzione sono i **wildcards** (caratteri jolly), rappresentati dal punto interrogativo `?`.

Wildcard Illimitato: `List`

`List` significa "una lista di un tipo sconosciuto". È utile per metodi che non dipendono dal tipo specifico degli elementi.


public void printList(List list) {
    for (Object elem : list) {
        System.out.print(elem + " ");
    }
}

// Questo metodo può accettare List, List, List
