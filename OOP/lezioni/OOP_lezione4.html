1. Il Problema della Traversa delle Collezioni

Nelle lezioni precedenti, abbiamo visto come definire gli ADT in modo robusto, mantenendo l'incapsulamento della rappresentazione interna. Ma come facciamo a permettere al client di accedere (leggere) tutti gli elementi di una collezione (es. tutti i numeri di un `IntSet`) senza rompere l'incapsulamento?

Consideriamo un `IntSet` e l'esigenza di calcolare la somma di tutti i suoi elementi:

Approccio 1: Metodi Custom nell'ADT (Non Flessibile)

Potremmo aggiungere un metodo `sum()` direttamente all'ADT `IntSet`.


public class IntSet {
    private List elements; // Rappresentazione interna

    public int sum() {
        int total = 0;
        for (Integer num : elements) { // Accedo direttamente alla rappresentazione
            total += num;
        }
        return total;
    }
}
💡 Pro e Contro
**Pro:** Rispettiamo l'incapsulamento (il client non vede la rappresentazione).
**Contro:** Se volessimo calcolare la somma dei quadrati, o la somma dei numeri pari, o il prodotto, dovremmo aggiungere un metodo diverso per ogni operazione, gonfiando l'ADT e violando il Single Responsibility Principle. L'ADT diventerebbe "troppo intelligente".

Approccio 2: Esporre la Rappresentazione (PERICOLOSO)

Potremmo esporre la rappresentazione interna con un getter pubblico (`public List getElements()`). Ma come visto, questo è un disastro per l'incapsulamento e la manutenibilità.

Approccio 3: Metodi Destruttivi (`choose()`/`remove()`)

Un metodo `choose()` che restituisce un elemento casuale e un `remove()` per eliminarlo dall'insieme permette di processare tutti gli elementi, ma distrugge l'insieme originale.


public int sum(IntSet s) { // METODO DANNOSO: modifica l'input
    int total = 0;
    while (s.size() > 0) {
        int element = s.choose(); // Prende un elemento
        s.remove(element);        // Lo rimuove!
        total += element;
    }
    return total;
}
⚠️ Non è una buona soluzione!
Questo approccio è distruttivo (l'insieme originale viene svuotato), inefficiente (molte rimozioni possono essere costose) e non flessibile (non posso fare più operazioni sullo stesso insieme).

2. Il Pattern Iterator

La soluzione elegante e standard al problema della traversa delle collezioni è il **Pattern Iterator**. Un iteratore è un oggetto che permette di accedere sequenzialmente agli elementi di una collezione senza esporre la sua struttura interna.

Interfaccia `java.util.Iterator`

Java fornisce un'interfaccia standard per gli iteratori. Tutte le collezioni (`List`, `Set`, `Map` tramite `entrySet()`) la implementano o la espongono.

  • boolean hasNext(): Restituisce `true` se ci sono ancora elementi da visitare.
  • E next(): Restituisce il prossimo elemento e avanza l'iteratore. Lancia `NoSuchElementException` se non ci sono più elementi.
  • void remove(): (Opzionale) Rimuove l'ultimo elemento restituito da `next()`. Solitamente lancia `UnsupportedOperationException` se non supportato.
💡 Vantaggi dell'Iteratore
  • Incapsulamento: Il client non vede come la collezione è implementata internamente.
  • Flessibilità: Permette di implementare diverse logiche di traversa (es. ordinata, inversa, filtrata) senza modificare l'ADT.
  • Riutilizzo del Codice Client: Il codice che attraversa la collezione è indipendente dal tipo specifico di collezione.

// Codice client universale con Iterator
List numbers = new ArrayList<>(); // Oppure new LinkedList, new TreeSet, etc.
// ... popola numbers ...

Iterator it = numbers.iterator(); // Ottengo un iteratore

int sum = 0;
while (it.hasNext()) { // C'è ancora un elemento?
    Integer num = it.next(); // Prendilo
    sum += num;
}
System.out.println("Somma: " + sum);

2.1. Implementazione di un Iteratore Custom

Per un nostro ADT (es. `IntSet`), possiamo implementare un iteratore personalizzato, spesso come classe interna (`private inner class`).

💡 Il "Snapshot"
Per assicurare che l'iteratore non venga influenzato da modifiche all'ADT originale durante la traversa, l'iteratore dovrebbe operare su una **copia (snapshot)** dei dati al momento della sua creazione. 

// Parte della classe IntSet
public class IntSet {
    private List elements; // Rappresentazione interna

    // ... costruttori, insert, remove, ecc. ...

    // Metodo pubblico che restituisce l'iteratore
    public Iterator iterator() {
        return new IntSetIterator(this); // Crea e restituisce un'istanza dell'iteratore interno
    }

    // Classe interna privata che implementa l'interfaccia Iterator
    private class IntSetIterator implements Iterator {
        private List snapshot; // La copia dei dati su cui iterare
        private int currentIndex = 0;

        // Il costruttore riceve l'istanza di IntSet e ne fa una copia difensiva
        public IntSetIterator(IntSet set) {
            // Nota: this.elements si riferisce al campo della classe IntSet esterna
            this.snapshot = new ArrayList<>(set.elements); 
            // Se l'iteratore deve essere ordinato, si ordina qui la snapshot:
            // Collections.sort(this.snapshot); 
        }

        @Override
        public boolean hasNext() {
            return currentIndex < snapshot.size();
        }

        @Override
        public Integer next() {
            if (!hasNext()) {
                throw new java.util.NoSuchElementException();
            }
            return snapshot.get(currentIndex++);
        }

        @Override
        public void remove() {
            // L'operazione remove() dell'iteratore spesso non è supportata
            throw new UnsupportedOperationException("Remove non supportato.");
        }
    }
}

2.2. La `ConcurrentModificationException`

Se un iteratore non opera su una copia (snapshot) e la collezione sottostante viene modificata durante la traversa, Java (nelle sue collezioni standard) lancia una `ConcurrentModificationException`. Questa è una "fail-fast exception": serve a segnalare immediatamente un problema, non a gestirlo.

⚠️ Esempio di `ConcurrentModificationException`

List names = new ArrayList<>(List.of("Alice", "Bob", "Charlie"));

Iterator it = names.iterator();
while (it.hasNext()) {
    String name = it.next();
    if (name.equals("Bob")) {
        names.remove("Bob"); // MODIFICA LA LISTA DURANTE L'ITERAZIONE DIRETTA
    }
}
// Questo codice lancerà ConcurrentModificationException al prossimo next()
// perché la lista è stata modificata 'dietro le quinte' dell'iteratore.

Soluzione per le collezioni standard: Usare l'iteratore stesso per le modifiche (`it.remove()`) o modificare la collezione solo dopo aver finito l'iterazione.

Per i nostri iteratori custom, la soluzione del **snapshot** previene questa eccezione, in quanto l'iteratore lavora su una copia isolata.

3. Introduzione alla Programmazione Funzionale in Java

Con Java 8, sono state introdotte le **Lambda Expressions** e la **Stream API**, che portano elementi di programmazione funzionale nel linguaggio. Questo permette di scrivere codice più conciso, leggibile e potente, specialmente per la manipolazione delle collezioni.

Astrazione del Comportamento: L'Evoluzione

Ricordi il problema di filtrare una lista di `Person` (es. persone maggiorenni)? Abbiamo visto diverse evoluzioni:

  1. Ciclo For Tradizionale: Logica di filtro mescolata alla logica di traversa.
  2. Metodo `hasLegalAge()` nella classe `Person`: Migliora l'incapsulamento del *dato*, ma non del *comportamento* di filtro.
  3. Classi Anonime con Interfaccia Custom (`MyTest`): Il comportamento di filtro viene passato come oggetto, ma la sintassi è verbosa.
  4. **Lambda Expressions (Java 8+):** Il comportamento di filtro (una funzione) viene passato in modo conciso.

// 3. Con Classe Anonima (prima di Java 8)
// Interfaccia: interface MyTest { boolean test(T t); }
// Uso:
List adults = new ArrayList<>();
for (Person p : people) {
    if (new MyTest() { // Classe anonima per il comportamento
        @Override
        public boolean test(Person p) {
            return p.getAge() >= 18;
        }
    }.test(p)) {
        adults.add(p);
    }
}

// 4. Con Lambda Expression (Java 8+)
// MyTest diventa un'interfaccia funzionale (con un solo metodo astratto)
// Uso:
List adultsLambda = new ArrayList<>();
for (Person p : people) {
    // Il comportamento di filtro (funzione) è espresso in linea
    if (((Person person) -> person.getAge() >= 18).test(p)) { 
        adultsLambda.add(p);
    }
}

Le lambda permettono di trattare il "comportamento" come un dato, passandolo come parametro o assegnandolo a variabili. Questo è fondamentale per la flessibilità del codice.

💡 Lambdas e "Effectively Final"
Le lambda possono "catturare" variabili locali dal contesto esterno, ma queste variabili devono essere `final` o "effectively final" (cioè, il loro valore non cambia dopo essere stato inizializzato). Questo impedisce modifiche inaspettate dello stato locale da parte della lambda.

3.1. Interfacce Funzionali Standard

Java 8 ha introdotto un pacchetto (`java.util.function`) con molte interfacce funzionali predefinite, per evitare di doverle scrivere ogni volta:

  • `Predicate`: Riceve un `T`, restituisce `boolean`. Usato per filtri (`test(T t)`). Es: `p -> p.getAge() >= 18`.
  • `Consumer`: Riceve un `T`, non restituisce nulla (`void`). Usato per azioni con side-effects (`accept(T t)`). Es: `p -> System.out.println(p.getName())`.
  • `Function`: Riceve un `T`, restituisce un `R`. Usato per trasformazioni (`apply(T t)`). Es: `p -> p.getName()`.
  • `Supplier`: Non riceve nulla, restituisce un `T`. Usato per produrre valori (`get()`). Es: `() -> new Person("Nuovo")`.

Esistono anche versioni per due argomenti (`BiPredicate`, `BiConsumer`, `BiFunction`) e versioni specializzate per tipi primitivi (`IntPredicate`, `LongFunction`, ecc.) per evitare autoboxing.

3.2. La Stream API di Java

La **Stream API** (introdotta con Java 8) è una delle più grandi innovazioni. Permette di elaborare collezioni di dati in modo dichiarativo e funzionale, in una pipeline di operazioni.

Un **Stream** è una sequenza di elementi che supporta operazioni funzionali. Non è una struttura dati; non modifica la sorgente; e le operazioni sono lazy (valutate solo quando necessario).

Flusso Tipico di un Stream

  1. Creazione dello Stream: Da una collezione (`list.stream()`), da un array (`Arrays.stream(array)`), da valori singoli (`Stream.of(...)`).
  2. Operazioni Intermedie (Lazy): Trasformano lo stream in un altro stream. Eseguite solo quando c'è un'operazione terminale. Esempi:
    • `filter(Predicate)`: Filtra elementi.
    • `map(Function)`: Trasforma ogni elemento.
    • `distinct()`: Rimuove duplicati.
    • `sorted()`: Ordina elementi.
  3. Operazioni Terminali (Eager): Producono un risultato o un side-effect, consumando lo stream. Esempi:
    • `forEach(Consumer)`: Esegue un'azione per ogni elemento.
    • `collect(Collector)`: Raccoglie gli elementi in una nuova collezione.
    • `count()`, `sum()`, `average()`, `min()`, `max()`.
    • `reduce()`: Combina gli elementi in un unico risultato.

import java.util.List;
import java.util.stream.Collectors;
import java.util.Arrays;

// Supponiamo di avere una lista di persone (come in Lezione 03)
// List people = ...;

// Esempio 1: Filtrare e stampare i nomi dei maggiorenni
System.out.println("Nomi maggiorenni:");
people.stream()
      .filter(p -> p.getAge() >= 18) // Operazione intermedia: filtra
      .map(Person::getName)         // Operazione intermedia: trasforma Person in String (Method Reference)
      .forEach(System.out::println); // Operazione terminale: stampa (Method Reference)

// Esempio 2: Raccogliere tutti i maggiorenni in una nuova lista
List adults = people.stream()
                            .filter(p -> p.getAge() >= 18)
                            .collect(Collectors.toList()); // Operazione terminale: raccoglie in List

// Esempio 3: Somma delle età dei maggiorenni
long totalAge = people.stream()
                      .filter(p -> p.getAge() >= 18)
                      .mapToInt(Person::getAge) // Mappa a IntStream per operazioni numeriche
                      .sum(); // Operazione terminale specifica per IntStream

// Esempio 4: Calcolare la media dei voti (assumendo una classe Grade con getScore())
List grades = Arrays.asList(new Grade(25), new Grade(30), new Grade(18));
double averageScore = grades.stream()
                            .mapToDouble(Grade::getScore)
                            .average() // Restituisce OptionalDouble
                            .orElse(0.0); // Se lo stream è vuoto, restituisce 0.0
System.out.println("Voto medio: " + averageScore);
💡 Method References
Le "Method References" (`ClassName::methodName`) sono una sintassi concisa per le lambda che chiamano semplicemente un metodo esistente. Migliorano la leggibilità.
