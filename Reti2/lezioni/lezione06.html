1. Protocolli Ausiliari di IP

Il protocollo IP è progettato per essere semplice e si occupa solo dell'inoltro "best-effort" dei pacchetti. Per funzionare correttamente, però, ha bisogno del supporto di altri protocolli che gestiscono compiti essenziali come la configurazione degli host, la mappatura degli indirizzi e la segnalazione degli errori. Questi protocolli operano "a fianco" di IP e sono fondamentali per l'operatività di qualsiasi rete.

2. ARP: Address Resolution Protocol

Problema: Per inviare un pacchetto IP a un altro host sulla stessa rete locale (LAN), un dispositivo ha bisogno di conoscere l'indirizzo MAC di destinazione per poter costruire il frame di livello 2 (es. Ethernet).

Soluzione: L'Address Resolution Protocol (ARP) si occupa di mappare dinamicamente un indirizzo IP a un indirizzo MAC.

2.1. Come Funziona ARP

Il processo è semplice e basato su un meccanismo di richiesta-risposta:

  1. L'host A vuole inviare un pacchetto all'IP di B, ma non conosce il suo MAC. Prima controlla nella sua ARP cache locale.
  2. Se l'informazione non è in cache, A costruisce una richiesta ARP contenente l'IP di B e la invia in broadcast sulla LAN. Il messaggio significa: "Chi ha l'IP `192.168.1.10`? Per favore, mandami il tuo indirizzo MAC".
  3. Tutti i dispositivi sulla LAN ricevono la richiesta, ma solo B (che possiede quell'IP) risponde.
  4. B invia una risposta ARP in unicast direttamente ad A, contenente il suo indirizzo MAC.
  5. A riceve la risposta, aggiorna la sua ARP cache e può finalmente inviare il pacchetto IP a B.
Punto chiave per l'esame: Se un host deve inviare un pacchetto a una rete esterna, non userà ARP per trovare il MAC della destinazione finale, ma per trovare il MAC del suo default gateway (router). Il pacchetto IP avrà come destinazione l'IP finale, ma il frame Ethernet avrà come destinazione il MAC del router.

3. DHCP: Dynamic Host Configuration Protocol

Problema: Configurare manualmente l'indirizzo IP, la subnet mask, il default gateway e i server DNS su ogni dispositivo di una rete è un'operazione noiosa, dispendiosa in termini di tempo e soggetta a errori.

Soluzione: Il Dynamic Host Configuration Protocol (DHCP) automatizza questo processo.

3.1. Il Processo DORA (Discover, Offer, Request, ACK)

Un host appena connesso alla rete ottiene la sua configurazione tramite uno scambio di 4 messaggi con un server DHCP:

sequenceDiagram
    participant Client
    participant Server
    Client->>Server: 1. DHCP DISCOVER (Broadcast)
    Server->>Client: 2. DHCP OFFER (Broadcast/Unicast)
    Client->>Server: 3. DHCP REQUEST (Broadcast)
    Server->>Client: 4. DHCP ACK (Broadcast/Unicast)
  1. Discover: Il client, non avendo ancora un IP, invia un messaggio in broadcast sulla rete: "C'è un server DHCP qui?".
  2. Offer: Uno o più server DHCP sulla rete rispondono con un'offerta, proponendo un indirizzo IP e altri parametri di configurazione.
  3. Request: Il client sceglie una delle offerte (di solito la prima che arriva) e invia un altro messaggio in broadcast per comunicare a tutti i server quale offerta ha accettato.
  4. ACK (Acknowledge): Il server scelto conferma l'assegnazione (chiamata "lease", affitto, perché ha una durata) e invia la configurazione finale.
Punto chiave per l'esame: Le domande su DHCP sono quasi sempre concettuali. Devi sapere a cosa serve, conoscere le 4 fasi dello scambio e capire cosa succede se il server non risponde (l'host si auto-configura con un indirizzo APIPA, `169.254.x.x`).

4. NAT: Network Address Translation

Problema: Gli indirizzi IPv4 pubblici sono una risorsa scarsa e ormai esaurita. Come si possono connettere a Internet le migliaia di dispositivi di una rete privata (aziendale o domestica) usando un solo (o pochi) indirizzi IP pubblici?

Soluzione: Il Network Address Translation (NAT). Un router NAT, posto al confine tra la rete privata e Internet, si occupa di tradurre gli indirizzi IP privati (es. `192.168.1.x`) nell'unico indirizzo IP pubblico a sua disposizione, e viceversa.

4.1. Come Funziona NAT/PAT

Il NAT semplice ("one-to-one") mappa un IP privato a un IP pubblico. Molto più comune è il PAT (Port and Address Translation), anche chiamato "NAT overload", che permette a più dispositivi privati di condividere un unico IP pubblico.

Il meccanismo si basa sulla traduzione non solo dell'IP, ma anche della porta sorgente:

  1. Traffico in Uscita: Un host privato (es. `192.168.1.10:50000`) invia un pacchetto a un server su Internet. Il router NAT intercetta il pacchetto, sostituisce l'IP e la porta sorgente con il proprio IP pubblico e una porta effimera univoca (es. `80.81.82.83:12345`) e memorizza questa mappatura `(192.168.1.10:50000 -> 80.81.82.83:12345)` in una tabella.
  2. Traffico in Entrata: Quando il server risponde a `80.81.82.83:12345`, il router NAT consulta la sua tabella, trova la mappatura originale e traduce l'IP e la porta di destinazione a `192.168.1.10:50000`, inoltrando il pacchetto all'host corretto nella rete privata.
Punto chiave per l'esame: Le domande su NAT sono spesso scenari "what-if". Ad esempio: "Cosa succede a una connessione TCP attiva se l'indirizzo IP pubblico del router NAT cambia?". La risposta è che la connessione si interrompe, perché i pacchetti di ritorno dal server verrebbero inviati all'indirizzo pubblico vecchio e non arriverebbero più al router.

5. ICMP: Internet Control Message Protocol

Problema: IP è inaffidabile e non ha meccanismi per segnalare errori. Cosa succede se un router non può inoltrare un pacchetto? O se la destinazione non esiste?

Soluzione: L'Internet Control Message Protocol (ICMP) è il protocollo di servizio usato da router e host per scambiarsi messaggi di controllo e di errore relativi al livello IP.

I messaggi ICMP più importanti per l'esame sono:

  • Destination Unreachable: Inviato quando un router o un host non può consegnare un pacchetto.
  • Time Exceeded: Inviato da un router quando scarta un pacchetto perché il suo TTL è arrivato a 0.
  • Echo Request / Echo Reply: Usati dal comando `ping` per verificare la raggiungibilità di un host.

5.1. Ping e Traceroute

Questi due strumenti di diagnostica, spesso oggetto di domande, si basano su ICMP.

  • Ping: Invia una serie di messaggi `ICMP Echo Request` a una destinazione e misura il tempo di attesa per le risposte (`ICMP Echo Reply`), calcolando così il **Round-Trip Time (RTT)**.
  • Traceroute (o tracert): Sfrutta in modo ingegnoso il campo TTL e i messaggi ICMP `Time Exceeded` per scoprire il percorso (la sequenza di router) verso una destinazione. Invia una serie di pacchetti con TTL crescente (1, 2, 3...):
    • Il primo pacchetto (TTL=1) viene scartato dal primo router, che risponde con un `ICMP Time Exceeded`, rivelando il suo indirizzo IP.
    • Il secondo pacchetto (TTL=2) passa il primo router, ma viene scartato dal secondo, che risponde a sua volta, e così via.
