2. Il Problema della Selezione

Definizione: (Minutaggio MP3: 01:33 - 01:47)

Dato un array (o vettore) A di lunghezza N e un intero i (con \(1 \le i \le N\)), il problema della selezione consiste nel determinare l'elemento che si troverebbe in posizione i se l'array A fosse ordinato in modo non decrescente.

Soluzione Base (non ottimale per questo contesto):

Una soluzione ovvia è ordinare l'intero array A e poi prendere l'elemento A[i]. Questo ha una complessità di \(\Theta(N \log N)\) se si usa un algoritmo di ordinamento efficiente. (Minutaggio MP3: 01:47 - 02:12)

L'obiettivo della lezione è trovare un metodo più efficiente, idealmente \(\Theta(N)\), per risolvere il problema della selezione.

3. Algoritmo "Select Naive" (Basato su Partition)

Questo algoritmo sfrutta la procedura Partition, già vista in QuickSort. (Minutaggio MP3: 03:39 - 04:00)

Idea dell'Algoritmo Select-Naive(A, p, q, i):

L'algoritmo cerca l'i-esimo elemento più piccolo nella porzione di array A[p...q].

  1. Caso Base: Se p == q (la porzione ha un solo elemento), restituisci A[p].
  2. Partiziona: Esegui r = Partition(A, p, q). Il pivot (originariamente A[q] o una sua variante) si trova ora in posizione r.
  3. Calcola il Rango del Pivot: Il rango del pivot A[r] all'interno della porzione A[p...q] è k = r - p + 1.
  4. Confronta e Ricorri:
    • Se i == k: Il pivot A[r] è l'elemento cercato. Restituiscilo. (Minutaggio MP3: 05:48 - 05:52)
    • Se i < k: L'elemento cercato è nella partizione sinistra A[p...r-1]. Richiama ricorsivamente Select-Naive(A, p, r-1, i). (Minutaggio MP3: 05:20 - 05:31)
    • Se i > k: L'elemento cercato è nella partizione destra A[r+1...q]. Richiama ricorsivamente Select-Naive(A, r+1, q, i-k). (Minutaggio MP3: 05:58 - 06:07)

// Pseudocodice Select Naive (dalla lezione, adattato per chiarezza)
// Cerca l'i-esimo elemento più piccolo in A[p...q]

Select-Naive(A, p, q, i_target) // i_target è il rango desiderato
  if p == q then 
    return A[p]

  // r è l'indice del pivot DOPO la partizione (indice globale nell'array A)
  r = Partition(A, p, q) 

  // k è il rango del pivot A[r] all'interno della sottoporzione A[p...q]
  // Se A[p...q] ha n' elementi, A[r] è il k-esimo di questi n' elementi.
  k = r - p + 1 

  if i_target == k then
    return A[r]  // Trovato!
  else if i_target < k then
    // L'elemento cercato è nella parte sinistra A[p...r-1]
    // Il suo rango (i_target) rimane lo stesso rispetto all'inizio di questa parte.
    return Select-Naive(A, p, r-1, i_target)
  else // i_target > k
    // L'elemento cercato è nella parte destra A[r+1...q]
    // Poiché abbiamo scartato k elementi (A[p...r]),
    // il nuovo rango da cercare nella parte destra è i_target - k.
    return Select-Naive(A, r+1, q, i_target - k)
Chiarimento sull'Indice Ricorsivo (Aggiunto):

Quando si ricorre sulla parte destra (i_target > k), il nuovo rango da cercare è i_target - k. Ad esempio, se cerchiamo il 7° elemento (i_target=7) e il pivot si piazza al 4° posto (k=4) della porzione corrente, significa che i 4 elementi più piccoli (incluso il pivot) sono a sinistra o sono il pivot stesso. Nella parte destra, che inizia dopo questi 4 elementi, l'elemento che era originariamente il 7° diventerà il (7-4) = 3° elemento più piccolo relativo a quella parte destra.

3.1. Complessità di "Select Naive"

La complessità dipende da come Partition divide l'array. (Minutaggio MP3: 06:07 - 06:52)

  • Caso Peggiore (\(\Theta(N^2)\)): Se Partition produce sempre una partizione massimamente sbilanciata (es. un lato con 0 elementi e l'altro con N-1, e si ricorre sempre sul lato N-1). L'equazione di ricorrenza è \(T(N) = T(N-1) + \Theta(N)\), che si risolve a \(\Theta(N^2)\). Questo è analogo al caso peggiore di QuickSort.
  • Caso Migliore/Medio (\(\Theta(N)\)): Se Partition divide l'array circa a metà (o in una frazione costante). L'equazione di ricorrenza è \(T(N) = T(N/2) + \Theta(N)\) (o \(T(\alpha N) + \Theta(N)\) con \(\alpha < 1\)). Questa si risolve a \(\Theta(N)\) (per il Master Theorem, Caso 3, o srotolandola).

Poiché "Select Naive" non garantisce \(\Theta(N)\) nel caso peggiore, si cerca un algoritmo migliore.

4. Algoritmo di Selezione Lineare O(N) nel Caso Peggiore (Median of Medians / BFPRT)

L'obiettivo è trovare un pivot per Partition in tempo lineare, in modo che la partizione risultante sia sempre "sufficientemente" bilanciata. Questo porta all'algoritmo noto come SELECT o Median-of-Medians (dagli autori Blum, Floyd, Pratt, Rivest, Tarjan). (Minutaggio MP3: 08:18 - 08:45)

4.1. Idea e Passaggi dell'Algoritmo SELECT(A, p, q, i_target)

(Minutaggio MP3: 08:45 - 09:50)

  1. Dividi in Gruppi di 5:

    Dividi la porzione A[p...q] (di \(n = q-p+1\) elementi) in \(\lceil n/5 \rceil\) gruppi. Ogni gruppo ha 5 elementi, tranne l'ultimo che potrebbe averne meno (se \(n\) non è multiplo di 5). Costo: \(\Theta(n)\) (per attraversare e raggruppare concettualmente).

    Esempio di divisione in gruppi (N elementi):

    G1,1G1,2G1,3G1,4G1,5 ... Gk,1Gk,2...Gk,m
    Mediana1 ... Medianak
     k = ceil(N/5) gruppi. L'ultimo gruppo Gk potrebbe avere m < 5 elementi.
  2. Trova la Mediana di Ciascun Gruppo:

    Per ognuno dei \(\lceil n/5 \rceil\) gruppi, trova la sua mediana. Poiché ogni gruppo ha al massimo 5 elementi, la mediana di un gruppo si trova in tempo costante \(\Theta(1)\) (es. con pochi confronti o ordinando il piccolo gruppo). Costo totale di questa fase: \(\lceil n/5 \rceil \cdot \Theta(1) = \Theta(n)\). Colleziona queste \(\lceil n/5 \rceil\) mediane in un nuovo array ausiliario `B`.

  3. Trova la Mediana delle Mediane (Pivot \(M\)):

    Richiama ricorsivamente l'algoritmo SELECT sull'array `B` (che contiene le \(\lceil n/5 \rceil\) mediane) per trovare la loro mediana. Chiamiamo questa "mediana delle mediane" \(M\). Questo \(M\) sarà il pivot per partizionare l'array originale A. Costo: \(T(\lceil n/5 \rceil)\).

  4. Partiziona l'Array Originale Attorno al Pivot \(M\):

    Usa una procedura Partition (che accetta un pivot esplicito) per partizionare A[p...q] attorno a \(M\). Sia r l'indice finale di \(M\) in A. Costo: \(\Theta(n)\).

  5. Verifica il Rango e Ricorri (come in Select-Naive):

    Sia k_pivot = r - p + 1 il rango del pivot \(M\) nella porzione A[p...q].

    • Se i_target == k_pivot, allora \(M\) è l'elemento cercato. Restituisci \(M\).
    • Se i_target < k_pivot, richiama ricorsivamente SELECT(A, p, r-1, i_target).
    • Se i_target > k_pivot, richiama ricorsivamente SELECT(A, r+1, q, i_target - k_pivot).

    La chiamata ricorsiva in questo passo avverrà su una porzione di dimensione al massimo \((7n/10) + \text{costante}\).

4.2. Analisi della "Bontà" del Pivot \(M\) (Mediana delle Mediane)

La scelta di \(M\) come pivot garantisce una buona partizione. (Minutaggio MP3: 09:50 - 11:30)

Consideriamo i \(\lceil n/5 \rceil\) gruppi. Immaginiamoli ordinati internamente e poi le loro mediane ordinate tra loro. \(M\) è la mediana di queste mediane.

Legenda: 'e' = elemento piccolo, 'm' = mediana del gruppo, 'g' = elemento grande del gruppo.

  • Almeno la metà dei \(\lceil n/5 \rceil\) gruppi hanno una mediana che è minore o uguale a \(M\). Questi sono circa \(\frac{1}{2} \cdot \frac{n}{5} = \frac{n}{10}\) gruppi.
  • In ognuno di questi \(\approx n/10\) gruppi, ci sono almeno 3 elementi che sono \(\le\) alla mediana del gruppo (i due più piccoli e la mediana stessa), e quindi sono anche \(\le M\).
  • Quindi, ci sono almeno \(3 \cdot (\frac{n}{10}) = \frac{3n}{10}\) elementi nell'array originale A che sono \(\le M\).
  • Simmetricamente, ci sono almeno \(\frac{3n}{10}\) elementi in A che sono \(\ge M\).

Questo implica che quando si partiziona A usando \(M\) come pivot, la chiamata ricorsiva (al passo 5) sarà su una porzione di dimensione al massimo \(n - \frac{3n}{10} = \frac{7n}{10}\) elementi (più un piccolo termine costante per gestire gli arrotondamenti e i casi base, che può essere espresso come \(7n/10 + 6\) per \(n\) abbastanza grande).

Approfondimento (Perché gruppi di 5 e non 3?) (Aggiunto):

Se si usassero gruppi di 3 elementi invece di 5:

  • Ci sarebbero \(n/3\) gruppi.
  • Si troverebbe la mediana di ogni gruppo di 3 (costo \(\Theta(n)\)).
  • Si troverebbe la mediana \(M\) di queste \(n/3\) mediane (costo \(T(n/3)\)).
  • Analizzando la bontà del pivot \(M\): \(M\) sarebbe maggiore o uguale ad almeno la metà delle mediane dei gruppi di 3 (\(\approx n/6\) mediane). Ognuna di queste mediane è maggiore o uguale a 2 elementi nel suo gruppo di 3. Quindi \(M\) sarebbe \(\ge 2 \cdot (n/6) = n/3\) elementi.
  • Simmetricamente, \(M\) sarebbe \(\le\) ad almeno \(n/3\) elementi.
  • La ricorsione successiva sarebbe su al massimo \(n - n/3 = 2n/3\) elementi.
  • L'equazione di ricorrenza diventerebbe \(T(n) \le T(n/3) + T(2n/3) + \Theta(n)\).
  • In questo caso, \(1/3 + 2/3 = 1\). Questa ricorrenza (simile a quella di MergeSort o del caso medio di QuickSort senza una riduzione netta) si risolve a \(\Theta(N \log N)\), non \(\Theta(N)\).
Ecco perché il "5" è cruciale: è il più piccolo numero dispari che garantisce che la somma delle frazioni delle chiamate ricorsive (\(1/5 + 7/10 = 9/10\)) sia strettamente minore di 1, portando a una complessità lineare.

4.3. Equazione di Ricorrenza e Complessità di SELECT

L'equazione di ricorrenza per il tempo di esecuzione \(T(n)\) nel caso peggiore di SELECT è: (Minutaggio MP3: 11:30 - 11:41 e poi la dimostrazione più formale basata sugli appunti PDF non è stata fatta a voce ma menzionata)

\( T(n) \le T(\lceil n/5 \rceil) + T(7n/10 + 6) + \Theta(n) \)

dove il termine \(\Theta(n)\) (che possiamo scrivere come \(a \cdot n\) per una costante \(a\)) rappresenta i costi dei passi 1 (divisione in gruppi), 2 (trovare mediane dei gruppi), e 4 (partizionamento).

Si vuole dimostrare per sostituzione che \(T(n) \le c \cdot n\) per qualche costante \(c > 0\).

Ipotesi Induttiva (HI): Assumiamo che \(T(k) \le c \cdot k\) per ogni \(k < n\).

Sostituendo nell'equazione di ricorrenza:

\( T(n) \le c \cdot (\lceil n/5 \rceil) + c \cdot (7n/10 + 6) + a \cdot n \)

Poiché \(\lceil n/5 \rceil \le n/5 + 1\):

\( T(n) \le c \cdot (n/5 + 1) + c \cdot (7n/10 + 6) + a \cdot n \)

\( T(n) \le c \cdot n/5 + c + 7cn/10 + 6c + a \cdot n \)

\( T(n) \le cn(1/5 + 7/10) + an + 7c \)

\( T(n) \le cn(2/10 + 7/10) + an + 7c \)

\( T(n) \le cn(9/10) + an + 7c \)

Ora, vogliamo dimostrare che \(cn(9/10) + an + 7c \le cn\).

\( an + 7c \le cn - cn(9/10) \)

\( an + 7c \le cn(1 - 9/10) \)

\( an + 7c \le cn(1/10) \)

Raccogliendo \(c\):

\( c(n/10 - 7) \ge an \)

Affinché questa disuguaglianza sia valida e si possa trovare una \(c > 0\), il termine \((n/10 - 7)\) deve essere strettamente positivo. Quindi, \(n/10 - 7 > 0 \implies n/10 > 7 \implies n > 70\).

Se \(n > 70\), allora \((n/10 - 7) > 0\), e possiamo scegliere:

\( c \ge \frac{an}{n/10 - 7} = \frac{10an}{n - 70} \)

Per \(n\) sufficientemente grande (ad esempio, se \(n \ge 140\), allora \(n-70 \ge n/2\)), abbiamo \(\frac{n}{n-70} \le \frac{n}{n/2} = 2\). Quindi, la condizione diventa \(c \ge 10a \cdot 2 = 20a\).

È possibile scegliere una tale costante \(c\) (es. \(c = 20a\)) purché \(n\) sia abbastanza grande (es. \(n \ge n_0 = 140\)). Per i valori di \(n < n_0\), la complessità \(T(n)\) è limitata da una costante (caso base), e possiamo scegliere \(c\) abbastanza grande da coprire anche questi casi base, ovvero \(c \ge T(n)/n\) per \(1 \le n < n_0\).

Conclusione: L'algoritmo SELECT ha una complessità temporale \(\Theta(N)\) nel caso peggiore.

4.4. Proprietà dell'Algoritmo SELECT (Median of Medians)

(Minutaggio MP3: 12:00 - 12:12 circa, per le proprietà)

  • Complessità Temporale: \(\Theta(N)\) nel caso peggiore.
  • Spazio Ausiliario: L'algoritmo non è in-place.
    • Richiede spazio per l'array `B` delle mediane dei gruppi, che ha dimensione \(\lceil n/5 \rceil = O(N)\).
    • Lo stack di ricorsione ha profondità \(O(\log N)\).
    Dominante è lo spazio \(O(N)\) per l'array `B`.
  • Stabilità: L'algoritmo non è stabile, a causa dell'uso della procedura Partition.
Considerazioni Pratiche (dalla Prof.ssa): Sebbene SELECT (median of medians) sia \(\Theta(N)\) nel caso peggiore, ha costanti moltiplicative elevate. In pratica, per valori di N non "eccessivamente grandi", l'algoritmo Randomized-Select (che ha complessità *attesa* \(\Theta(N)\)) tende ad essere più veloce. SELECT garantisce però le prestazioni nel caso peggiore.

5. QuickSort Ottimizzato (Worst-Case \(\Theta(N \log N)\))

Ora possiamo utilizzare l'algoritmo SELECT (con complessità \(\Theta(N)\) nel caso peggiore) per costruire una versione di QuickSort che garantisca una complessità \(\Theta(N \log N)\) anche nel caso peggiore. (Minutaggio MP3: 12:12 - 12:22)

5.1. Idea dell'Algoritmo Quicksort_ott(A, p, q)

L'idea è di usare SELECT per trovare il mediano della porzione corrente dell'array e usare questo mediano come pivot per Partition.

  1. Se p < q:
    1. Trova il Mediano: Calcola l'indice del mediano della porzione A[p...q]. Ad esempio, se la porzione ha \(n' = q-p+1\) elementi, il mediano si trova al rango \(i_{med} = \lfloor (n'+1)/2 \rfloor\) relativo a questa porzione. Chiama mediano_valore = SELECT(A, p, q, i_{med}) per ottenere il valore del mediano. (Costo \(\Theta(N)\), dove \(N = q-p+1\)).
    2. Partiziona Attorno al Mediano: Usa una procedura Partition-Attorno-Valore(A, p, q, mediano_valore) che partiziona A[p...q] usando mediano_valore come pivot. Questa procedura potrebbe dover prima trovare un'occorrenza di mediano_valore, scambiarla con A[q], e poi chiamare la Partition di Lomuto. Sia r l'indice finale del pivot. (Costo \(\Theta(N)\)).
    3. Chiamate Ricorsive:
      • Quicksort_ott(A, p, r - 1)
      • Quicksort_ott(A, r + 1, q)

5.2. Complessità di Quicksort_ott

Sia \(N = q-p+1\) la dimensione della porzione corrente.

  • Il passo 1.a (trovare il mediano con SELECT) costa \(\Theta(N)\).
  • Il passo 1.b (partizionare attorno al mediano) costa \(\Theta(N)\).
  • Poiché il pivot scelto è il mediano, le due chiamate ricorsive (passo 1.c) avvengono su sottoproblemi di dimensione circa \(N/2\).

L'equazione di ricorrenza per il tempo di esecuzione \(T(N)\) di Quicksort_ott è:

\( T(N) = 2 \cdot T(N/2) + \Theta(N) \)

Questa è la classica ricorrenza di MergeSort e del caso migliore/medio di QuickSort, che si risolve (per il Master Theorem, Caso 2) a:

\( T(N) = \Theta(N \log N) \)

Questa versione di QuickSort ha quindi una complessità \(\Theta(N \log N)\) garantita anche nel caso peggiore, perché la scelta del pivot (il mediano) assicura sempre partizioni bilanciate.

Costo Pratico (dalla Prof.ssa): Nonostante la garanzia teorica, questo "Quicksort Ottimizzato" ha costanti moltiplicative più elevate rispetto al Randomized-QuickSort, a causa del costo \(\Theta(N)\) per trovare il mediano ad ogni passo di ricorsione. In pratica, Randomized-QuickSort è spesso preferito.

6. Esercizi Assegnati per Casa

La professoressa ha concluso la parte teorica sugli algoritmi di selezione e sul QuickSort ottimizzato. Ha poi assegnato il seguente esercizio: (Minutaggio MP3: 12:22 - 12:49)

6.1. Esercizio: Majority Candidate

Testo del Problema:

Dato un vettore (array) A di N elementi, determinare se esiste un elemento x che compare più di N/2 volte (cioè, con frequenza strettamente maggiore della metà della dimensione dell'array). Se tale elemento esiste, restituirlo; altrimenti, indicare che non esiste (o restituire un valore speciale).

Vincoli Richiesti dalla Professoressa:

  • Complessità Temporale: \(\Theta(N)\)
  • Complessità Spaziale: \(\Theta(1)\) (cioè, l'algoritmo deve essere in-place o usare una quantità costante di spazio ausiliario).
Risoluzione Dettagliata (Aggiunta da AI): Algoritmo di Boyer-Moore (Voting Algorithm)

Questo problema è un classico e può essere risolto efficientemente con l'algoritmo di voto di Boyer-Moore, che soddisfa i vincoli richiesti.

Idea dell'Algoritmo: (Minutaggio MP3: 12:50 - 13:36, la professoressa inizia a descrivere l'idea generale)

L'algoritmo si basa sull'idea che se un elemento è maggioritario, "sopravviverà" a un processo di eliminazione a coppie con elementi diversi. Immagina di far "combattere" gli elementi: se due elementi diversi si incontrano, si eliminano a vicenda; se due elementi uguali si incontrano, uno "rafforza" l'altro.

Si articola in due fasi:

Fase 1: Trovare un candidato per l'elemento maggioritario.

  1. Si inizializzano due variabili:
    • candidate: per memorizzare il candidato corrente all'elemento maggioritario. Può essere inizializzato, ad esempio, con il primo elemento dell'array.
    • count: un contatore, inizializzato a 1 (se `candidate` è il primo elemento) o a 0.
    La professoressa suggerisce di inizializzare `count = 0` e poi, nel ciclo, se `count == 0`, si prende l'elemento corrente come nuovo `candidate`.
  2. Si scorre l'array A da sinistra a destra (o dall'indice 0 a N-1):
    • Se count == 0:
      • Si imposta candidate = A[i] (l'elemento corrente dell'array diventa il nuovo candidato).
      • Si imposta count = 1.
    • Altrimenti (se count > 0):
      • Se A[i] == candidate: si incrementa count (il candidato ha trovato un "alleato").
      • Se A[i] != candidate: si decrementa count (il candidato ha incontrato un "nemico" e si sono "annullati").

Al termine di questa fase, se esiste un elemento maggioritario, esso deve essere il valore rimasto in candidate. Se non esiste un elemento maggioritario, candidate conterrà un valore qualsiasi dell'array, ma non è detto che sia significativo.

Fase 2: Verificare se il candidato è effettivamente l'elemento maggioritario.

Poiché la Fase 1 garantisce solo un *candidato*, è necessario verificare se questo candidato compare effettivamente più di N/2 volte. (Minutaggio MP3: 13:36 - 13:40)

  1. Si re-inizializza un contatore (chiamiamolo verify_count) a 0.
  2. Si scorre nuovamente l'intero array A.
  3. Per ogni elemento A[j] dell'array, se A[j] == candidate (il candidato trovato nella Fase 1), si incrementa verify_count.
  4. Dopo la scansione, se verify_count > N/2, allora candidate è l'elemento maggioritario e viene restituito.
  5. Altrimenti, si conclude che non esiste un elemento maggioritario nell'array.

Pseudocodice Completo:


Find-Majority-Element(A)
  N = A.length
  if N == 0 then
    return "Array vuoto" // o un'eccezione

  // Fase 1: Trova il candidato
  candidate = A[0] // Inizializzazione alternativa: candidate = null, count = 0
  count = 1      // Se si inizia con A[0], count parte da 1.

  for i = 1 to N-1 do // Se si parte da A[0], il ciclo parte da 1
    if A[i] == candidate then
      count = count + 1
    else
      count = count - 1
    
    if count == 0 then
      candidate = A[i] // Nuovo candidato
      count = 1        // Se A[i] è l'ultimo elemento, questo diventerà il candidato.
                       // È importante che se il ciclo finisce con count=0, 
                       // l'ultimo A[i] che ha azzerato count diventi il candidato.
                       // Una logica più robusta è:
                       // if count == 0 then { candidate = A[i]; count = 1; }
                       // else if A[i] == candidate then { count++; }
                       // else { count--; }
                       // (La versione della prof. nel file MP3 è corretta e più concisa)

  // Fase 2: Verifica il candidato
  verify_count = 0
  for i = 0 to N-1 do
    if A[i] == candidate then
      verify_count = verify_count + 1
      
  if verify_count > N / 2 then
    return candidate
  else
    return "Nessun elemento maggioritario" // o null, o un flag
Nota sullo Pseudocodice della Fase 1 (Aggiunto):

La logica della Fase 1 descritta a voce dalla professoressa (e riportata nella mia analisi precedente della lezione) è: 


// Logica Fase 1 (come da spiegazione orale della prof)
candidate = null // o un valore fittizio non presente nell'array
count = 0
for i = 0 to N-1 do
  if count == 0 then
    candidate = A[i]
    count = 1
  else if A[i] == candidate then
    count = count + 1
  else // A[i] != candidate
    count = count - 1
Questa versione è più generale e gestisce anche il caso di array vuoto implicitamente (se N=0, il ciclo non parte, candidate rimane null).

Correttezza (Intuizione): (Minutaggio MP3: 13:40 - 13:45)

L'elemento maggioritario, chiamiamolo `m`, per definizione compare più della metà delle volte. Ogni volta che `m` "incontra" un elemento diverso da sé, entrambi vengono "eliminati" (il `count` del candidato `m` scende, o se un altro elemento era candidato, il suo `count` scende). Poiché ci sono più `m` che "non-`m`", `m` non può essere eliminato completamente. Alla fine della Fase 1, se un elemento maggioritario esiste, `candidate` deve contenerlo. La Fase 2 poi lo conferma.

Complessità:

  • Tempo: La Fase 1 esegue una singola scansione dell'array (\(\Theta(N)\)). La Fase 2 esegue un'altra singola scansione dell'array (\(\Theta(N)\)). Il costo totale è \(\Theta(N) + \Theta(N) = \Theta(N)\).
  • Spazio: L'algoritmo utilizza solo un numero costante di variabili (candidate, count, i, verify_count). Quindi, la complessità spaziale è \(\Theta(1)\).

L'algoritmo di Boyer-Moore soddisfa pienamente i vincoli richiesti.

7. Approfondimenti e Correzioni (Aggiunti dall'AI)

Approfondimento: L'Osservazione \(T(N) = T(\alpha N) + T(\beta N) + \Theta(N)\)

Durante la lezione (Minutaggio MP3: 16:15 - 17:30 circa, riferendosi agli appunti PDF non forniti qui), la professoressa ha discusso un'osservazione importante per l'analisi di algoritmi divide et impera:

Se un'equazione di ricorrenza è della forma:

\( T(N) = T(\alpha N) + T(\beta N) + f(N) \)

dove \(f(N) = \Theta(N)\), e le costanti \(\alpha > 0\), \(\beta > 0\) sono tali che \(\alpha + \beta < 1\), allora la soluzione della ricorrenza è \(T(N) = \Theta(N)\).

Dimostrazione per Induzione (Idea):

Vogliamo dimostrare \(T(N) \le cN\) per qualche costante \(c > 0\).

Assumiamo (Ipotesi Induttiva) \(T(k) \le ck\) per \(k < N\).

\( T(N) \le c(\alpha N) + c(\beta N) + bN \) (dove \(bN\) rappresenta \(\Theta(N)\))

\( T(N) \le cN(\alpha + \beta) + bN \)

Vogliamo che \(cN(\alpha + \beta) + bN \le cN\).

\( bN \le cN - cN(\alpha + \beta) \)

\( bN \le cN(1 - (\alpha + \beta)) \)

\( b \le c(1 - (\alpha + \beta)) \)

Poiché per ipotesi \(\alpha + \beta < 1\), allora \(1 - (\alpha + \beta)\) è una costante positiva. Chiamiamola \(\delta = 1 - (\alpha + \beta) > 0\).

Quindi, \(b \le c\delta \implies c \ge b/\delta\).

È possibile scegliere una tale costante \(c\), quindi l'ipotesi induttiva è verificata e \(T(N) = O(N)\). Poiché il lavoro è almeno \(\Omega(N)\) (per il termine \(f(N)\)), allora \(T(N) = \Theta(N)\).

Questa osservazione è fondamentale per capire perché l'algoritmo SELECT (Median of Medians) ha complessità \(\Theta(N)\), dato che le sue chiamate ricorsive sono su \(N/5\) e \(7N/10\) elementi, e \(1/5 + 7/10 = 9/10 < 1\).

Chiarimento sull'Esempio di Boyer-Moore (Aggiunto):

Nell'esempio A = [2, 2, 1, 1, 1, 2, 1]:

Fase 1 (versione della prof.ssa):

  • count=0, candidate=null
  • i=0, A[0]=2: count=0 -> candidate=2, count=1
  • i=1, A[1]=2: A[1]==candidate -> count=2
  • i=2, A[2]=1: A[2]!=candidate -> count=1
  • i=3, A[3]=1: A[3]!=candidate -> count=0
  • i=4, A[4]=1: count=0 -> candidate=1, count=1
  • i=5, A[5]=2: A[5]!=candidate -> count=0
  • i=6, A[6]=1: count=0 -> candidate=1, count=1

Candidato finale della Fase 1 è 1. La Fase 2 conferma che 1 compare 4 volte, che è > 7/2.

8. Conclusioni della Lezione

In questa lezione abbiamo approfondito il problema della Selezione e come una sua soluzione efficiente possa portare a un QuickSort con prestazioni garantite nel caso peggiore.

  • L'algoritmo SELECT (Median of Medians) permette di trovare l'i-esimo elemento più piccolo in un array in tempo \(\Theta(N)\) nel caso peggiore, sebbene con costanti moltiplicative elevate e non essendo in-place.
  • Utilizzando SELECT per scegliere il pivot (il mediano), QuickSort_ott ottiene una complessità \(\Theta(N \log N)\) garantita nel caso peggiore.
  • È stato presentato l'algoritmo di Boyer-Moore per il problema del "Majority Candidate", che opera in tempo \(\Theta(N)\) e spazio \(\Theta(1)\).

Comprendere questi algoritmi e le loro analisi di complessità è fondamentale per scegliere la strategia giusta in base ai requisiti specifici di un problema.
