1. Ripresa Analisi QuickSort: Dimostrazione Formale del Caso Peggiore

La lezione inizia riprendendo l'analisi della complessità di QuickSort, concentrandosi sulla dimostrazione formale del caso peggiore.

Equazione di Ricorrenza Generale per QuickSort:

\( T(n) = \begin{cases} \Theta(1) & \text{se } n \le 1 \\ T(m) + T(n-m-1) + \Theta(n) & \text{se } n > 1 \end{cases} \)

dove \(0 \le m \le n-1\) è la dimensione della partizione sinistra dopo l'esecuzione di Partition (che costa \(\Theta(n)\)).

Per semplificare, la professoressa sostituisce le notazioni asintotiche con costanti:

\( T(n) = \begin{cases} a & \text{se } n \le 1 \\ T(m) + T(n-m-1) + b \cdot n & \text{se } n > 1 \end{cases} \)

Caso Peggiore: Partizione Massimamente Sbilanciata

Si verifica quando \(m=0\) o \(m=n-1\). In entrambi gli scenari, l'equazione si riduce a:

\( T(n) = T(n-1) + b \cdot n \) (ignorando \(T(0)\) che è una costante)

Avevamo già visto intuitivamente che questo porta a \(\Theta(n^2)\).

Dimostrazione Formale che \(T(n) \in O(n^2)\) per il Caso Peggiore (Metodo di Sostituzione)

Vogliamo dimostrare che \(T(n) \le c \cdot n^2\) per qualche costante \(c > 0\) e per \(n \ge n_0\).

Passo Induttivo:

Assumiamo (Ipotesi Induttiva - HI) che \(T(k) \le c \cdot k^2\) per ogni \(k < n\).

Per il caso peggiore, la complessità è data da:

\( T(n) = \max_{0 \le m \le n-1} \{ T(m) + T(n-m-1) + b \cdot n \} \)

Applicando l'HI:

\( T(n) \le \max_{0 \le m \le n-1} \{ c \cdot m^2 + c \cdot (n-m-1)^2 + b \cdot n \} \)

Per semplificare, assumiamo di poter scegliere una costante \(c\) tale che \(c \ge b\). Allora \(b \cdot n \le c \cdot n\). (Questa assunzione dovrà essere verificata alla fine).

\( T(n) \le \max_{0 \le m \le n-1} \{ c \cdot m^2 + c \cdot (n-m-1)^2 + c \cdot n \} \)
\( T(n) \le c \cdot \max_{0 \le m \le n-1} \{ m^2 + (n-m-1)^2 + n \} \)

Consideriamo la funzione \(f(m) = m^2 + (n-m-1)^2 + n\). Questa è una parabola in \(m\) con concavità verso l'alto (il coefficiente di \(m^2\) è \(1+1=2 > 0\)). Il suo massimo nell'intervallo \([0, n-1]\) si troverà agli estremi.

  • Per \(m=0\): \(f(0) = 0^2 + (n-1)^2 + n = n^2 - 2n + 1 + n = n^2 - n + 1\).
  • Per \(m=n-1\): \(f(n-1) = (n-1)^2 + (n-(n-1)-1)^2 + n = (n-1)^2 + 0^2 + n = n^2 - n + 1\).

Quindi, \(\max_{0 \le m \le n-1} \{ f(m) \} = n^2 - n + 1\).

Sostituendo nella disuguaglianza per \(T(n)\):

\( T(n) \le c \cdot (n^2 - n + 1) \)

Vogliamo dimostrare che \(c \cdot (n^2 - n + 1) \le c \cdot n^2\) (perché questa è la nostra tesi \(T(n) \le c \cdot n^2\)).

\( c \cdot n^2 - c \cdot n + c \le c \cdot n^2 \)

\( -c \cdot n + c \le 0 \)

\( c \cdot (1 - n) \le 0 \)

Poiché abbiamo assunto \(c > 0\), questa disuguaglianza è vera se \(1 - n \le 0\), cioè se \(n \ge 1\).

Caso Base dell'Induzione:

Per \(n=1\), \(T(1) = a\). Vogliamo dimostrare che \(a \le c \cdot 1^2\), cioè \(a \le c\).

Condizioni sulla Costante \(c\):

Perché la dimostrazione sia valida, dobbiamo poter scegliere una costante \(c\) che soddisfi:

  1. \(c > 0\) (dalla definizione di \(O(\cdot)\)).
  2. \(c \ge b\) (dall'assunzione fatta per semplificare la maggiorazione).
  3. \(c \ge a\) (dal caso base).

Possiamo quindi scegliere \(c = \max(a, b)\) (assumendo \(a, b > 0\)) o un valore leggermente più grande se necessario per coprire il \(\Theta(1)\) iniziale in modo stretto. La condizione \(n \ge 1\) per il passo induttivo è soddisfatta per tutti gli \(n\) rilevanti.

Conclusione: Abbiamo dimostrato che \(T(n) \in O(n^2)\) nel caso peggiore. Poiché sappiamo che esistono input (es. array già ordinato con la partizione di Lomuto) che inducono questo comportamento, e quindi \(T(n) \in \Omega(n^2)\) per il caso peggiore, possiamo concludere che la complessità di QuickSort nel caso peggiore è \(\Theta(n^2)\).

2. Analisi del Caso Medio di QuickSort (\(\Theta(N \log N)\))

Per analizzare il caso medio, si fanno delle assunzioni sulla distribuzione degli input o sulla scelta del pivot.

Assunzione Chiave:

Si assume che, dopo la procedura Partition, la dimensione \(m\) della prima sottoparte (elementi \(\le\) pivot) sia uniformemente distribuita nell'intervallo \([0, n-1]\). Cioè, ogni possibile valore di \(m\) (da 0 a \(n-1\)) ha probabilità \(1/n\) di verificarsi. Questa assunzione è ragionevole se il pivot è scelto casualmente (Randomized QuickSort) o se si mediano su tutte le possibili permutazioni dell'input.

Sia \(T_M(n)\) il tempo di esecuzione medio di QuickSort su \(n\) elementi.

L'equazione di ricorrenza per il caso medio diventa:

\( T_M(n) = \left( \frac{1}{n} \sum_{m=0}^{n-1} [T_M(m) + T_M(n-m-1)] \right) + \Theta(n) \)

Il termine \(\Theta(n)\) è il costo di Partition. La sommatoria calcola il valore atteso del costo ricorsivo, mediando su tutte le possibili dimensioni \(m\) della prima partizione.

Semplificazione della Sommatoria

Osserviamo la struttura della sommatoria: \(\sum_{m=0}^{n-1} [T_M(m) + T_M(n-m-1)]\).

Espandendola, vediamo che ogni termine \(T_M(k)\) (per \(0 \le k \le n-1\)) compare due volte:

  • Quando \(m=0\): \(T_M(0) + T_M(n-1)\)
  • Quando \(m=1\): \(T_M(1) + T_M(n-2)\)
  • ...
  • Quando \(m=n-2\): \(T_M(n-2) + T_M(1)\)
  • Quando \(m=n-1\): \(T_M(n-1) + T_M(0)\)

Quindi, la sommatoria è uguale a \(2 \sum_{m=0}^{n-1} T_M(m)\).

Sostituendo nell'equazione di ricorrenza e usando \(b \cdot n\) per \(\Theta(n)\):

\( T_M(n) = \frac{2}{n} \sum_{m=0}^{n-1} T_M(m) + b \cdot n \)

Risoluzione dell'Equazione di Ricorrenza (Cenno)

La professoressa indica che la risoluzione di questa equazione di ricorrenza non è banale e di solito si fa per sostituzione, ipotizzando una soluzione del tipo \(T_M(k) \le c \cdot k \log k\).

Passaggi Comuni per la Risoluzione (non svolti in dettaglio dalla prof, ma menzionati come tecniche standard):

  1. Moltiplicare entrambi i membri per \(n\): \( n T_M(n) = 2 \sum_{m=0}^{n-1} T_M(m) + b \cdot n^2 \).
  2. Scrivere la stessa equazione per \(n-1\): \( (n-1) T_M(n-1) = 2 \sum_{m=0}^{n-2} T_M(m) + b \cdot (n-1)^2 \).
  3. Sottrarre la seconda dalla prima per eliminare la sommatoria:
    \( n T_M(n) - (n-1) T_M(n-1) = 2 T_M(n-1) + b \cdot n^2 - b \cdot (n-1)^2 \)
    \( n T_M(n) = (n+1) T_M(n-1) + b(2n-1) \) (circa \(2bn\))
  4. Dividere per \(n(n+1)\) per ottenere una forma telescopica (o quasi) e risolvere.

La professoressa rimanda al libro di testo per la dimostrazione completa, che conferma la soluzione.

Conclusione per il Caso Medio:

\( T_M(n) = \Theta(n \log n) \)

Questo risultato è molto importante: in media, o con randomizzazione, QuickSort è efficiente quanto MergeSort e Heapsort in termini di complessità asintotica.

3. Proprietà di QuickSort (Breve Ripasso)

La professoressa fa un rapido ripasso delle proprietà di QuickSort discusse nella lezione precedente:

  • In-Place:
    • La procedura Partition di Lomuto è in-place.
    • La ricorsione di QuickSort usa lo stack. Nel caso peggiore, la profondità è \(O(N)\). Nel caso migliore/medio, è \(O(\log N)\).
    • Quindi, non è strettamente in-place (O(1) spazio ausiliario) a causa dello stack. Può essere resa tale (con stack \(O(\log N)\) nel caso peggiore) ottimizzando la ricorsione (ricorrendo sulla parte più piccola e iterando sulla più grande).
  • Stabile:
    • QuickSort, con la partizione di Lomuto, non è stabile. Gli scambi possono alterare l'ordine relativo di elementi uguali.

4. Domande e Risposte su QuickSort

La professoressa apre una sessione di domande e risposte su QuickSort.

Domanda Studente: "Riguardo l'altezza dell'albero di ricorsione: nel caso peggiore (complessità \(\Theta(N^2)\)) l'altezza è \(N\), e nel caso migliore/medio (\(\Theta(N \log N)\)) l'altezza è \(\log N\). Ma il lavoro ad ogni livello dell'albero di ricorsione è sempre \(N\)?"

Risposta Professoressa:

  • No, non è sempre \(N\) ad ogni livello nel caso peggiore.
    • Nel caso peggiore (es. albero di ricorsione degenere, "a pettine"), il primo livello di partizione costa \(\Theta(N)\). La chiamata ricorsiva successiva opera su \(N-1\) elementi e costa \(\Theta(N-1)\) per la sua partizione, e così via. La somma del lavoro è \(\Theta(N) + \Theta(N-1) + \Theta(N-2) + \dots + \Theta(1) = \Theta(N^2)\). Qui l'altezza è \(N\), ma il lavoro per livello decresce.
  • Nel caso migliore/medio (es. albero di ricorsione bilanciato), l'altezza è \(\Theta(\log N)\).
    • Al livello 0 (radice), la partizione costa \(\Theta(N)\).
    • Al livello 1, ci sono due sottoproblemi di dimensione circa \(N/2\). La partizione per ciascuno costa \(\Theta(N/2)\). Il lavoro totale a questo livello è \(2 \cdot \Theta(N/2) = \Theta(N)\).
    • In generale, ad ogni livello \(k\) dell'albero di ricorsione bilanciato, il lavoro totale per partizionare tutti i sottoproblemi a quel livello è \(\Theta(N)\).
    • Poiché ci sono \(\Theta(\log N)\) livelli, il lavoro totale è \(\Theta(N) \cdot \Theta(\log N) = \Theta(N \log N)\).

Domanda Studente (implicita dalla discussione): "Se QuickSort ha un caso peggiore quadratico, perché si dice che è veloce o perché lo si usa?"

Risposta Professoressa (ribadita):

  • Prestazioni Medie Eccellenti: In media, specialmente con la randomizzazione (che rende il caso peggiore molto improbabile), QuickSort è \(\Theta(N \log N)\).
  • Basse Costanti Moltiplicative: Le operazioni interne di QuickSort (confronti e scambi in Partition) sono molto efficienti e tendono ad avere costanti "nascoste" nella notazione \(\Theta\) più piccole rispetto ad altri algoritmi \(\Theta(N \log N)\) come MergeSort (che ha l'overhead della copia/fusione di array) o Heapsort (che ha una struttura dati più complessa da mantenere).
  • Buona Località di Riferimento: Partition accede agli elementi dell'array in modo prevalentemente sequenziale, il che è favorevole per le prestazioni della cache della CPU.

5. Il Problema della Selezione (Selection Problem)

La professoressa introduce un nuovo problema, strettamente correlato a QuickSort: il Problema della Selezione (o problema dell'i-esimo ordine statistico).

Definizione del Problema:

Dato un insieme (o array) \(A\) di \(n\) numeri (non necessariamente distinti) e un intero \(i\) (con \(1 \le i \le n\)), trovare l'elemento \(x \in A\) che è il \(i\)-esimo elemento più piccolo di \(A\). Cioè, se l'array \(A\) fosse ordinato, l'elemento cercato sarebbe quello in posizione \(i\).

Casi Particolari:

  • Se \(i=1\), si cerca il minimo.
  • Se \(i=n\), si cerca il massimo.
  • Se \(n\) è dispari e \(i = (n+1)/2\), si cerca la mediana.
  • Se \(n\) è pari, si possono definire due mediane:
    • Mediana inferiore: \(i = \lfloor (n+1)/2 \rfloor\)
    • Mediana superiore: \(i = \lceil (n+1)/2 \rceil\) (o \(n/2 + 1\))
    La professoressa di solito si riferisce alla mediana inferiore quando \(n\) è pari.

Soluzione Banale (Basata sull'Ordinamento)

L'approccio più ovvio per risolvere il problema della selezione è:

  1. Ordinare l'array \(A\). Questo richiede tempo \(\Theta(n \log n)\) usando un algoritmo efficiente come MergeSort o Heapsort.
  2. Restituire l'elemento che si trova in posizione \(i\) dell'array ordinato. Questo richiede tempo \(\Theta(1)\).

La complessità totale di questa soluzione banale è \(\Theta(n \log n)\).

Obiettivo: Algoritmo Più Efficiente

La domanda è: possiamo fare di meglio? L'obiettivo è trovare un algoritmo per il problema della selezione che abbia una complessità temporale lineare, cioè \(\Theta(n)\).

Si cercherà prima un algoritmo randomizzato con tempo atteso lineare, e poi un algoritmo deterministico con tempo lineare nel caso peggiore.

6. Algoritmo Randomized-Select (Selezione Randomizzata)

L'algoritmo Randomized-Select sfrutta la stessa idea di base di Randomized-QuickSort e della procedura Randomized-Partition.

6.1. Idea dell'Algoritmo Randomized-Select(A, p, q, i)

L'algoritmo cerca l'\(i\)-esimo elemento più piccolo nella porzione di array A[p...q].

  1. Caso Base: Se la porzione contiene un solo elemento (cioè p == q), allora questo è l'elemento cercato (assumendo che `i` sia coerentemente 1 in questo caso). Restituisci A[p].
  2. Partiziona: Chiama Randomized-Partition(A, p, q) per partizionare l'array attorno a un pivot scelto casualmente. Sia r l'indice finale del pivot A[r].
  3. Determina il Rango del Pivot: Il pivot A[r] è ora al suo posto corretto rispetto alla porzione A[p...q]. Calcola il suo rango (o ordine statistico) k all'interno di questa porzione: k = r - p + 1. (Cioè, A[r] è il k-esimo elemento più piccolo in A[p...q]).
  4. Confronta e Ricorri:
    • Se i == k: Il pivot A[r] è esattamente l'\(i\)-esimo elemento più piccolo che stavamo cercando. Restituisci A[r].
    • Se i < k: L'\(i\)-esimo elemento più piccolo deve trovarsi nella parte sinistra dell'array partizionato, cioè in A[p...r-1]. Richiama ricorsivamente Randomized-Select(A, p, r-1, i). (Il rango `i` rimane lo stesso perché stiamo cercando all'interno della prima parte).
    • Se i > k: L'\(i\)-esimo elemento più piccolo deve trovarsi nella parte destra dell'array partizionato, cioè in A[r+1...q]. Tuttavia, poiché abbiamo "scartato" i primi k elementi (quelli in A[p...r]), ora stiamo cercando l'(i-k)-esimo elemento più piccolo all'interno della sottoporzione A[r+1...q]. Richiama ricorsivamente Randomized-Select(A, r+1, q, i-k).

La differenza chiave rispetto a QuickSort è che Randomized-Select fa una sola chiamata ricorsiva, non due. Questo è ciò che permette di ottenere potenzialmente una complessità lineare.

6.2. Pseudocodice di Randomized-Select

(Corrisponde agli appunti della professoressa a pagina 8 del PDF "Nota 9 nov 2020 (2).pdf")


Randomized-Select(A, p, q, i)
  // A: array, p: indice inizio, q: indice fine, i: i-esimo elemento da trovare (1 ≤ i ≤ q-p+1)
  
  if p == q then
    return A[p]
  
  r ← Randomized-Partition(A, p, q) // Partiziona A[p...q] e ottieni l'indice del pivot
  k ← r - p + 1                    // Rango del pivot A[r] nella porzione A[p...q]
  
  if i == k then
    return A[r]                      // Il pivot è l'elemento cercato
  else if i < k then
    return Randomized-Select(A, p, r - 1, i) // Cerca nella parte sinistra
  else // i > k
    return Randomized-Select(A, r + 1, q, i - k) // Cerca nella parte destra, aggiornando i

6.3. Esempio di Esecuzione di Randomized-Select

Consideriamo l'array A = [3, 2, 9, 0, 7, 5, 4, 8, 6, 1]. Vogliamo trovare il 7°-esimo elemento più piccolo (i=7). Quindi, la chiamata iniziale è Randomized-Select(A, 1, 10, 7) (assumendo indicizzazione da 1).

Esecuzione (ipotetica, poiché Randomized-Partition è casuale):

  1. Chiamata: Randomized-Select(A, 1, 10, 7)
    • p=1, q=10. p != q.
    • Supponiamo che Randomized-Partition(A, 1, 10) scelga come pivot A[x] e che dopo la partizione, A[4] = 3 (il pivot finisce in posizione 4). Quindi r=4.
    • L'array potrebbe essere (ad esempio): [0, 1, 2, 3, 7, 5, 4, 8, 6, 9]
    • k = r - p + 1 = 4 - 1 + 1 = 4. (Il pivot 3 è il 4° elemento più piccolo in A[1..10]).
    • Confrontiamo i=7 con k=4. Poiché i > k (7 > 4), cerchiamo nella parte destra.
    • Nuova chiamata: Randomized-Select(A, r+1, q, i-k) cioè Randomized-Select(A, 5, 10, 7-4=3). Ora cerchiamo il 3° elemento più piccolo nella porzione A[5..10] = [7, 5, 4, 8, 6, 9].
  2. Chiamata: Randomized-Select(A, 5, 10, 3)
    • p=5, q=10. p != q.
    • Supponiamo che Randomized-Partition(A, 5, 10) partizioni la porzione [7, 5, 4, 8, 6, 9] e che il pivot scelto (diciamo 6) finisca in A[8] (indice globale, che è il 4° elemento della porzione A[5..10]). Quindi r=8 (relativo alla chiamata, ma qui r è l'indice globale).
    • L'array nella porzione A[5..10] potrebbe diventare: [4, 5, ?, 6, ?, ?] (es. [4, 5, ?, 6, 7, 8, 9], supponendo che A[8] ora contenga 6). Esempio di A completo: [0, 1, 2, 3, 4, 5, ?, 6, ?, ?] Supponiamo, per l'esempio, che A[5..10] dopo la partizione (con pivot 6) sia: [4, 5, 6, 7, 8, 9]. Il pivot 6 è in A[7] (posizione globale). Quindi r=7.
    • k = r - p + 1 = 7 - 5 + 1 = 3. (Il pivot 6 è il 3° elemento più piccolo in A[5..10]).
    • Confrontiamo i=3 (passato alla chiamata) con k=3. Poiché i == k, il pivot A[r] = A[7] = 6 è l'elemento cercato.
    • Restituisci A[7] = 6.

Quindi, il 7° elemento più piccolo dell'array originale è 6.

6.4. Analisi della Complessità di Randomized-Select

Caso Peggiore (\(\Theta(N^2)\)):

Si verifica se Randomized-Partition sceglie costantemente un pivot "cattivo", che produce una partizione massimamente sbilanciata (es. il pivot è sempre il minimo o il massimo della porzione corrente). In questo scenario, la dimensione del problema si riduce solo di 1 ad ogni chiamata ricorsiva.

L'equazione di ricorrenza diventa:

\( T(N) = T(N-1) + \Theta(N) \)

Questa si risolve a \(T(N) = \Theta(N^2)\).

Caso Migliore (\(\Theta(N)\)):

Si verifica se Randomized-Partition sceglie costantemente un pivot "buono", che divide l'array circa a metà. La chiamata ricorsiva successiva avviene su una porzione di dimensione circa \(N/2\).

L'equazione di ricorrenza diventa:

\( T(N) = T(N/2) + \Theta(N) \)

Usando il Master Theorem:

  • \(a = 1\) (numero di sottoproblemi)
  • \(b = 2\) (fattore di riduzione della dimensione)
  • \(f(N) = \Theta(N)\) (costo di Partition)

Calcoliamo \(N^{\log_b a} = N^{\log_2 1} = N^0 = 1\).

Confrontiamo \(f(N) = \Theta(N)\) con \(N^{\log_b a} = 1\). Poiché \(N = \Omega(N^{0+\epsilon})\) per \(\epsilon \le 1\) (es. \(\epsilon = 1\), quindi \(N = \Omega(N^1)\)), siamo nel Caso 3 del Master Theorem.

Dobbiamo verificare la condizione di regolarità: \(a \cdot f(N/b) \le d \cdot f(N)\) per qualche costante \(d < 1\).

\(1 \cdot \Theta(N/2) \le d \cdot \Theta(N)\).

Sia \(f(N) = c_0 N\). Allora \(c_0 (N/2) \le d \cdot c_0 N\). Dividendo per \(c_0 N\), otteniamo \(1/2 \le d\). Questa condizione richiede \(d < 1\). Possiamo scegliere, ad esempio, \(d = 1/2\) (o un valore tra \(1/2\) e \(1\)). La condizione \(1/2 \le d < 1\) è soddisfatta (es. \(d = 3/4\)).

Quindi, per il Caso 3 del Master Theorem, la soluzione è \(T(N) = \Theta(f(N)) = \Theta(N)\).

Nel caso migliore, Randomized-Select ha complessità \(\Theta(N)\).

Caso Medio (Tempo Atteso):

L'analisi del caso medio per Randomized-Select è più complessa (simile a quella di Randomized QuickSort, ma più semplice perché c'sola una chiamata ricorsiva). Si può dimostrare che il tempo di esecuzione atteso di Randomized-Select è \(\Theta(N)\).

Intuizione: Anche se a volte la partizione è sbilanciata, in media la dimensione del problema si riduce di una frazione costante. Ad esempio, se il pivot cade nel "mezzo" (es. tra il 25° e il 75° percentile), la dimensione si riduce di almeno 1/4. La probabilità che questo accada è 1/2. Se il pivot cade male, la probabilità è comunque bilanciata. La somma dei lavori attesi forma una serie geometrica convergente moltiplicata per \(N\), portando a \(\Theta(N)\).

7. Algoritmo di Selezione Lineare nel Caso Peggiore (SELECT / Median-of-Medians)

Esiste un algoritmo deterministico, spesso chiamato semplicemente SELECT o algoritmo della "Mediana delle Mediane", che garantisce una complessità di \(\Theta(N)\) anche nel caso peggiore per il problema della selezione. Fu sviluppato da Blum, Floyd, Pratt, Rivest e Tarjan (BFPRT).

L'idea chiave è trovare un pivot "buono" in tempo lineare, che garantisca che le partizioni risultanti non siano mai troppo sbilanciate.

7.1. Passaggi dell'Algoritmo SELECT(A, p, q, i)

  1. Dividi in Gruppi di 5:

    Dividi gli \(n = q-p+1\) elementi della porzione corrente A[p...q] in \(\lceil n/5 \rceil\) gruppi. Ogni gruppo ha 5 elementi, tranne possibilmente l'ultimo che potrebbe averne meno (da 1 a 4). Questa operazione richiede tempo \(\Theta(n)\) per scorrere l'array e formare i gruppi concettualmente.

    Esempio divisione in gruppi di 5 (n=17):

    G1.1G1.2G1.3G1.4G1.5 | G2.1G2.2G2.3G2.4G2.5 | G3.1G3.2G3.3G3.4G3.5 | G4.1G4.2
  2. Trova la Mediana di Ciascun Gruppo:

    Per ognuno dei \(\lceil n/5 \rceil\) gruppi, trova la sua mediana. Poiché ogni gruppo ha al massimo 5 elementi, trovare la mediana di un gruppo (ad esempio, ordinando il gruppetto con Insertion Sort) richiede tempo costante \(\Theta(1)\) per gruppo. Il numero di gruppi è \(\approx n/5\). Quindi, il costo totale per trovare tutte queste mediane è \(\lceil n/5 \rceil \cdot \Theta(1) = \Theta(n)\).

    Mediane dei gruppi (evidenziate):

    xxM1xx | xxM2xx | xxM3xx | M4x
  3. Trova la Mediana delle Mediane (Pivot \(x\)):

    Raccogli tutte le \(\lceil n/5 \rceil\) mediane trovate al passo precedente in un nuovo (concettuale) array. Chiama ricorsivamente SELECT su questo array di mediane per trovare la loro mediana. Questa mediana delle mediane, \(x\), sarà usata come pivot per partizionare l'array originale. Il costo di questa chiamata ricorsiva è \(T(\lceil n/5 \rceil)\).

  4. Partiziona l'Array Originale attorno al Pivot \(x\):

    Usa una variante della procedura Partition (che può prendere un pivot specifico come input, invece di sceglierlo) per partizionare l'array originale A[p...q] attorno al pivot \(x\) trovato al passo 3. Sia r l'indice in cui si trova \(x\) dopo la partizione. Questa operazione di partizione costa \(\Theta(n)\).

  5. Verifica il Rango e Ricorri (come in Randomized-Select):

    Sia k = r - p + 1 il rango del pivot \(x\) nella porzione A[p...q].

    • Se i == k, allora A[r] (cioè \(x\)) è l'elemento cercato. Restituisci \(x\).
    • Se i < k, l'elemento cercato è nella parte sinistra. Richiama ricorsivamente SELECT(A, p, r-1, i).
    • Se i > k, l'elemento cercato è nella parte destra. Richiama ricorsivamente SELECT(A, r+1, q, i-k).
    Il costo di questa chiamata ricorsiva sarà su una porzione di dimensione al più \((7n/10) + \text{costante}\) (vedremo perché tra poco).

7.2. Analisi della "Bontà" del Pivot (Mediana delle Mediane)

La chiave dell'efficienza nel caso peggiore di questo algoritmo risiede nella scelta del pivot \(x\) (la mediana delle mediane). Questo pivot garantisce che le partizioni non siano mai troppo sbilanciate.

Argomentazione (illustrata a pagina 9 del PDF):

Consideriamo gli elementi \(\le x\):

  • Poiché \(x\) è la mediana delle \(\lceil n/5 \rceil\) mediane dei gruppi, almeno la metà di queste mediane dei gruppi sono \(\le x\). Il numero di tali mediane è \(\approx \frac{1}{2} \cdot \frac{n}{5} = \frac{n}{10}\).
  • Per ciascuno di questi \(\approx n/10\) gruppi la cui mediana è \(\le x\), ci sono almeno 3 elementi nel gruppo che sono \(\le\) alla mediana del gruppo (la mediana stessa e i due elementi più piccoli del gruppo). Quindi, questi 3 elementi sono anche \(\le x\).
  • Questo ci dà un totale di almeno \(3 \cdot \frac{n}{10} = \frac{3n}{10}\) elementi dell'array originale che sono \(\le x\). (Ignoriamo per ora il gruppo che contiene \(x\) stesso e l'eventuale gruppo incompleto, per semplificare il lower bound).

Consideriamo gli elementi \(\ge x\):

  • Simmetricamente, almeno la metà delle mediane dei gruppi sono \(\ge x\).
  • Per ciascuno di questi \(\approx n/10\) gruppi, ci sono almeno 3 elementi nel gruppo che sono \(\ge\) alla mediana del gruppo (la mediana stessa e i due elementi più grandi). Quindi, questi 3 elementi sono anche \(\ge x\).
  • Questo ci dà un totale di almeno \(\frac{3n}{10}\) elementi dell'array originale che sono \(\ge x\).

Conclusione sulla Partizione:

Se almeno \(\frac{3n}{10}\) elementi sono \(\le x\) e almeno \(\frac{3n}{10}\) elementi sono \(\ge x\), allora quando si partiziona attorno a \(x\):

  • La partizione sinistra (elementi \(\le x\), escluso \(x\)) conterrà al massimo \(n - \frac{3n}{10} = \frac{7n}{10}\) elementi.
  • La partizione destra (elementi \(\ge x\), escluso \(x\)) conterrà al massimo \(n - \frac{3n}{10} = \frac{7n}{10}\) elementi.

Quindi, la chiamata ricorsiva al passo 5 dell'algoritmo SELECT avverrà su una porzione di dimensione al più \(\approx \frac{7n}{10}\) (più precisamente, \(\frac{7n}{10} + 6\) per gestire gli arrotondamenti e i casi limite, ma asintoticamente è \(\frac{7n}{10}\)).

7.3. Equazione di Ricorrenza e Complessità di SELECT (Caso Peggiore)

Sia \(T(n)\) il tempo di esecuzione nel caso peggiore dell'algoritmo SELECT su \(n\) elementi.

L'equazione di ricorrenza è (considerando i costi dei 5 passi):

\( T(n) \le \underbrace{O(n)}_{\text{Passo 1 (dividi)}} + \underbrace{O(n)}_{\text{Passo 2 (mediane gruppi)}} + \underbrace{T(\lceil n/5 \rceil)}_{\text{Passo 3 (ricorsione su mediane)}} + \underbrace{O(n)}_{\text{Passo 4 (partition)}} + \underbrace{T(7n/10 + 6)}_{\text{Passo 5 (ricorsione su partizione)}} \)

Combinando i termini lineari:

\( T(n) \le T(\lceil n/5 \rceil) + T(7n/10 + 6) + O(n) \)

Vogliamo dimostrare per sostituzione che \(T(n) \le c \cdot n\) per qualche costante \(c\).

Ipotesi Induttiva: \(T(k) \le c \cdot k\) per \(k < n\).

Sostituendo nell'equazione (e usando \(a \cdot n\) per \(O(n)\)):

\( T(n) \le c \cdot (\lceil n/5 \rceil) + c \cdot (7n/10 + 6) + a \cdot n \)

Possiamo maggiorare \(\lceil n/5 \rceil \le n/5 + 1\) (o semplicemente \(n/5\) per \(n\) grande, ma la professoressa usa \(n/5\) e assorbe le costanti).

\( T(n) \le c \cdot (n/5) + c \cdot (7n/10) + 6c + a \cdot n \)

\( T(n) \le c \cdot n \left( \frac{1}{5} + \frac{7}{10} \right) + 6c + a \cdot n \)

\( T(n) \le c \cdot n \left( \frac{2}{10} + \frac{7}{10} \right) + 6c + a \cdot n \)

\( T(n) \le c \cdot n \left( \frac{9}{10} \right) + a \cdot n + 6c \)

Vogliamo dimostrare che \(c \cdot n \left( \frac{9}{10} \right) + a \cdot n + 6c \le c \cdot n\).

\( a \cdot n + 6c \le c \cdot n - c \cdot n \left( \frac{9}{10} \right) \)

\( a \cdot n + 6c \le c \cdot n \left( 1 - \frac{9}{10} \right) \)

\( a \cdot n + 6c \le c \cdot n \left( \frac{1}{10} \right) \)

Questa disuguaglianza deve valere per \(n \ge n_0\). Riscriviamola come:

\( c \left( \frac{n}{10} - 6 \right) \ge a \cdot n \)

Perché questa sia vera, il termine \(\left( \frac{n}{10} - 6 \right)\) deve essere positivo, quindi \(\frac{n}{10} > 6 \Rightarrow n > 60\). Se \(n > 60\) (ad esempio \(n_0 \approx 70-80\) per avere un margine), possiamo scegliere \(c\) tale che:

\( c \ge \frac{a \cdot n}{\frac{n}{10} - 6} = \frac{10 \cdot a \cdot n}{n - 60} \)

Per \(n\) grande, il termine \(\frac{n}{n-60}\) tende a 1. Quindi, se \(n\) è abbastanza grande, possiamo scegliere \(c \ge 10a\) (ad esempio \(c = 20a\) per essere sicuri e coprire i casi base per \(n < n_0\)).

Gestione dei Casi Base: Per valori di \(n < n_0\) (dove \(n_0\) è il valore per cui la disuguaglianza \(\frac{n}{10}-6 > 0\) e la scelta di \(c\) funzionano, es. \(n_0 \approx 80-140\) a seconda del libro), si può assumere che \(T(n)\) sia limitato da una costante (es. si usa un altro algoritmo come l'ordinamento e poi selezione). Si sceglie \(c\) abbastanza grande da coprire \(T(n) \le cn\) anche per questi piccoli \(n\).

Conclusione per SELECT (Caso Peggiore):

\( T(n) = \Theta(n) \)

7.4. Considerazioni Pratiche sull'Algoritmo SELECT (Median-of-Medians)

Nonostante l'algoritmo SELECT (Median-of-Medians) garantisca una complessità lineare \(\Theta(n)\) nel caso peggiore, in pratica:

  • Costanti Moltiplicative Alte: Le costanti nascoste nella notazione \(\Theta(n)\) sono significativamente più grandi rispetto a quelle di Randomized-Select (nel suo caso medio). I vari passaggi (divisione in gruppi, calcolo mediane dei gruppi, chiamata ricorsiva sulle mediane, partizione) introducono un overhead considerevole.
  • Prestazioni Relative: Per valori di \(n\) non estremamente grandi, Randomized-Select (con il suo tempo atteso \(\Theta(n)\) e un caso peggiore \(\Theta(n^2)\) che è statisticamente improbabile) tende ad essere più veloce in pratica.
  • Utilità: L'algoritmo SELECT (Median-of-Medians) è importante teoricamente perché dimostra che la selezione può essere fatta in tempo lineare deterministico. Diventa preferibile quando una **garanzia stretta sul tempo di esecuzione nel caso peggiore** è cruciale, anche a costo di una performance media leggermente inferiore.

8. Conclusione e Prossimi Argomenti

La lezione ha coperto in dettaglio l'analisi di QuickSort (caso peggiore e medio) e ha introdotto il problema della selezione, presentando due algoritmi:

  • Randomized-Select: tempo atteso \(\Theta(n)\), caso peggiore \(\Theta(n^2)\).
  • SELECT (Median-of-Medians): tempo nel caso peggiore \(\Theta(n)\).

Prossimo Argomento (Anticipato dalla Professoressa):

Nella lezione successiva, si vedrà come utilizzare l'algoritmo SELECT (che trova il pivot mediano o quasi-mediano in tempo lineare) per costruire una versione di QuickSort che abbia una complessità di \(\Theta(n \log n)\) garantita anche nel caso peggiore. Questo algoritmo è talvolta chiamato "Worst-Case QuickSort" o "Median-of-Medians QuickSort".

L'idea sarà di usare SELECT per scegliere il pivot in Partition, garantendo così partizioni bilanciate.
