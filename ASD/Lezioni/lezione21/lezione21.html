1. Introduzione e Recap sugli Alberi Binari di Ricerca (BST)

La professoressa inizia la lezione riprendendo il discorso sugli Alberi Binari di Ricerca (BST). Viene fatto un breve riepilogo della definizione fondamentale:

Un BST è un albero binario in cui, per ogni nodo x:
  • Tutte le chiavi nel sottoalbero sinistro di x sono minori di x.key.
  • Tutte le chiavi nel sottoalbero destro di x sono maggiori di x.key.

La lezione di oggi si concentrerà sulle operazioni fondamentali che si possono eseguire su questa struttura dati, in particolare le operazioni di ricerca e inserimento. Fa riferimento agli appunti "Nota 10 dic 2020 (2).pdf".

1.1. Altezza di un BST

Prima di analizzare le operazioni, la professoressa discute l'altezza \(h\) di un BST con \(N\) chiavi. A differenza di strutture come le Heap, un BST non ha vincoli sulla sua "forma" o bilanciamento. Di conseguenza:

  • Caso Migliore (Albero Bilanciato): Se l'albero è ben bilanciato, la sua altezza sarà logaritmica rispetto al numero di nodi. \(h \in \Omega(\log N)\).
  • Caso Peggiore (Albero Degenere): Se l'albero degenera in una lista (ad esempio, inserendo elementi già ordinati), la sua altezza sarà lineare. \(h \in O(N)\).

Quindi, in generale, l'altezza \(h\) di un BST con \(N\) nodi è compresa tra \(\Omega(\log N)\) e \(O(N)\).

Questa variabilità nell'altezza avrà un impatto diretto sulla complessità delle operazioni.

2. Operazioni di Ricerca sui BST

La professoressa inizia l'analisi delle operazioni di ricerca, che sono particolarmente efficienti sui BST grazie alla loro proprietà di ordinamento.

2.1. Ricerca del Massimo e del Minimo

Trovare l'elemento con la chiave minima o massima in un BST è un'operazione molto semplice.

Ricerca del Massimo:

Per la proprietà del BST, le chiavi più grandi si trovano sempre nel sottoalbero destro. Per trovare la chiave massima, si deve seguire il percorso più a destra possibile.

  1. Si parte dalla radice dell'albero.
  2. Si continua a scendere nel figlio destro.
  3. Ci si ferma quando si raggiunge un nodo che non ha un figlio destro (cioè, il suo puntatore destro è `NIL`). Questo nodo contiene la chiave massima.
Approfondimento: il Massimo può avere un figlio sinistro?

Sì. Come sottolineato dalla professoressa, il nodo contenente il valore massimo non deve necessariamente essere una foglia (senza figli). Deve solo non avere un figlio destro. Può tranquillamente avere un figlio sinistro, che conterrà valori maggiori di quelli nel resto del sottoalbero, ma comunque minori del massimo stesso.

Ricerca del Minimo:

L'operazione è simmetrica. Per trovare la chiave minima:

  1. Si parte dalla radice.
  2. Si continua a scendere nel figlio sinistro.
  3. Ci si ferma quando si raggiunge un nodo che non ha un figlio sinistro.

2.1.1. Pseudocodice e Complessità

La professoressa presenta due versioni per la ricerca del massimo: una ricorsiva e una iterativa.

Versione Ricorsiva:


BST-Max(x) // x è il nodo da cui partire
  if x.right == NIL then
    return x // Trovato il nodo con chiave massima
  else
    return BST-Max(x.right)

Versione Iterativa (con ciclo `while`):


BST-Max-While(T)
  x = T.root
  if x == NIL then return NIL // Albero vuoto

  while (x.right != NIL) do
    x = x.right
  
  return x

Gestione del Caso Base (Albero Vuoto): La professoressa sottolinea che queste procedure, per essere robuste, devono gestire il caso in cui l'albero sia vuoto. Nello pseudocodice iterativo, questo è gestito esplicitamente. In quello ricorsivo, la chiamata iniziale (il "main") dovrebbe verificare se T.root è NIL prima di chiamare BST-Max(T.root).

Complessità:

  • Il percorso seguito è un singolo ramo dell'albero.
  • Nel caso peggiore, questo ramo è il più lungo possibile.
  • La complessità temporale è quindi proporzionale all'altezza dell'albero: \(\Theta(h)\).
  • Poiché \(h\) può variare da \(\log N\) a \(N\), la complessità in termini di \(N\) è \(O(N)\).
Confronto con Visita In-Order (domanda di uno studente):

Uno studente suggerisce di trovare il massimo eseguendo una visita In-Order e prendendo l'ultimo elemento. La professoressa chiarisce che, sebbene corretto, questo approccio avrebbe una complessità \(\Theta(N)\) anche nel caso migliore, perché richiederebbe di visitare tutti i nodi. La ricerca diretta è molto più efficiente, specialmente per alberi bilanciati dove costa solo \(\Theta(\log N)\).

2.2. Ricerca di una Chiave Specifica

L'obiettivo è trovare se un nodo con una data chiave k esiste nell'albero e, in caso affermativo, restituire un puntatore a quel nodo.

Logica:

  1. Si parte dalla radice.
  2. In un generico nodo x:
    • Se la chiave cercata k è uguale a x.key, l'elemento è stato trovato.
    • Se k è minore di x.key, si continua la ricerca nel sottoalbero sinistro.
    • Se k è maggiore di x.key, si continua la ricerca nel sottoalbero destro.
  3. Se durante la discesa si raggiunge un puntatore a NIL, significa che la chiave k non è presente nell'albero.

2.2.1. Pseudocodice e Complessità


BST-Search(x, k) // Cerca la chiave k partendo dal nodo x
  // Caso base: se il nodo è NIL o contiene la chiave, restituisci il nodo
  if x == NIL or k == x.key then
    return x
  
  // Passo ricorsivo
  if k < x.key then
    // Cerca nel sottoalbero sinistro
    return BST-Search(x.left, k)
  else
    // Cerca nel sottoalbero destro
    return BST-Search(x.right, k)
Correzioni e Note dalla Professoressa:
  1. Restituzione dei valori: Nelle chiamate ricorsive, è fondamentale usare `return BST-Search(...)` per propagare il risultato verso l'alto. Un errore comune è omettere il `return`.
  2. Gestione di NIL (Lazy Evaluation): La condizione `if x == NIL or k == x.key` funziona perché i linguaggi di programmazione moderni usano la valutazione "short-circuit" per gli operatori logici. Se `x == NIL` è vero, l'espressione `k == x.key` non viene valutata, evitando un errore di accesso a un puntatore nullo.

Complessità: Anche in questo caso, l'algoritmo segue un singolo percorso dalla radice verso una foglia (o un nodo intermedio). La complessità è \(\Theta(h)\) nel caso peggiore, che si traduce in \(O(N)\).

2.3. Ricerca del Successore e del Predecessore

Questa è un'operazione più sofisticata. Dato un nodo x, il suo successore è il nodo y che ha la più piccola chiave tra tutte quelle maggiori di x.key. In altre parole, è l'elemento che verrebbe subito dopo x in una visita In-Order.

Per trovare il successore di un nodo x, si distinguono due casi principali.

2.3.1. Caso 1: Il nodo x ha un sottoalbero destro non vuoto

Se il figlio destro di x non è NIL, allora il successore di x è il nodo con la chiave minima nel sottoalbero destro di x.

Per trovarlo, basta partire dal figlio destro di x (x.right) e scendere sempre a sinistra finché possibile.

2.3.2. Caso 2: Il nodo x non ha un sottoalbero destro

Se il figlio destro di x è NIL, il successore di x è il suo più basso antenato (genitore, nonno, ecc.) per il quale x si trova nel sottoalbero sinistro.

Per trovarlo, si risale l'albero da x usando i puntatori parent. Ci si ferma al primo antenato y tale che il nodo da cui si è arrivati (x o uno dei suoi antenati) è il figlio sinistro di y.

Intuizione: Finché si risale da un figlio destro, significa che il genitore ha una chiave più piccola ed è già stato visitato nell'In-Order. Il primo "svoltamento a sinistra" che si fa risalendo indica il primo nodo con una chiave più grande.

Per trovare il successore del nodo 7 (blu), che non ha un sottoalbero destro, si risale l'albero:

  1. Si sale al genitore 5 (giallo). Poiché 7 è un figlio destro, si continua a salire.
  2. Si sale al genitore 10 (viola). Poiché 5 è un figlio sinistro, questo è il primo "svoltamento a sinistra" che si incontra, quindi 10 è il successore.

Caso Limite: Se si risale fino alla radice e si scopre che x era l'elemento massimo dell'albero (si è sempre risaliti da un figlio destro), il puntatore al genitore diventerà `NIL`. In questo caso, x non ha successore.

2.3.3. Pseudocodice di BST-Successor


BST-Successor(x)
  // Caso 1: il nodo x ha un sottoalbero destro
  if x.right != NIL then
    return BST-Min(x.right) // Il successore è il minimo del sottoalbero destro

  // Caso 2: il nodo x non ha un sottoalbero destro
  else
    y = x.parent // Inizia a risalire dall'antenato
    // Continua a risalire finché y non è NIL (radice raggiunta)
    // e finché x è il figlio destro di y.
    while (y != NIL and x == y.right) do
      x = y
      y = y.parent
    
    return y // y è il successore (o NIL se x era il massimo)

Complessità: \(\Theta(h)\) o \(O(N)\), poiché si percorre un singolo cammino verso il basso o verso l'alto.

Esercizio (dalla Professoressa): Scrivere il codice per BST-Predecessor

Soluzione (Aggiunta da AI): La logica è perfettamente simmetrica.


BST-Predecessor(x)
  // Caso 1: il nodo x ha un sottoalbero sinistro
  if x.left != NIL then
    return BST-Max(x.left) // Il predecessore è il massimo del sottoalbero sinistro

  // Caso 2: il nodo x non ha un sottoalbero sinistro
  else
    y = x.parent
    // Continua a risalire finché y non è NIL
    // e finché x è il figlio sinistro di y.
    while (y != NIL and x == y.left) do
      x = y
      y = y.parent
    
    return y // y è il predecessore (o NIL se x era il minimo)

3. Inserimento in un BST (BST-Insert)

L'inserimento di un nuovo nodo z in un BST deve preservare la proprietà del BST. Il nuovo nodo verrà sempre inserito come una foglia.

3.1. Idea dell'Algoritmo

  1. Cerca la Posizione: Si scende nell'albero partendo dalla radice, come se si stesse cercando la chiave del nuovo nodo z.key.
  2. Mantieni traccia del Genitore: Durante la discesa, è fondamentale mantenere un puntatore al "genitore" del nodo corrente. Questo perché quando la ricerca termina trovando un puntatore NIL, quel puntatore NIL è la posizione in cui il nuovo nodo z deve essere agganciato, e il puntatore "genitore" ci dice a quale nodo agganciarlo. Si usano due puntatori: x che scende e y che lo segue ("genitore di x").
  3. Aggancia il Nuovo Nodo: Una volta che x diventa NIL, y punterà al nodo che diventerà il genitore di z. A questo punto:
    • Si imposta z.parent = y.
    • Si confronta z.key con y.key per decidere se z deve diventare il figlio sinistro o destro di y.
  4. Caso Speciale (Albero Vuoto): Se l'albero è inizialmente vuoto, y rimarrà NIL. In questo caso, il nuovo nodo z diventa la radice dell'albero.

3.2. Pseudocodice di BST-Insert


BST-Insert(T, z) // T è l'albero, z è il nuovo nodo da inserire
  y = NIL      // Puntatore al "genitore", che segue x
  x = T.root   // Puntatore che scende nell'albero
  
  // Scendi nell'albero per trovare la posizione di inserimento
  while (x != NIL) do
    y = x // Salva il genitore
    if z.key < x.key then
      x = x.left
    else
      x = x.right
      
  // Ora y è il genitore del nuovo nodo z, e x è NIL
  z.parent = y
  
  // Gestisci il caso di albero vuoto
  if y == NIL then
    T.root = z // z diventa la radice
  // Altrimenti, aggancia z a y
  else if z.key < y.key then
    y.left = z
  else
    y.right = z

3.4. Complessità dell'Inserimento

L'algoritmo di inserimento esegue una discesa dalla radice fino a una foglia (o una posizione vuota). Il numero di passi è limitato dall'altezza dell'albero.

La complessità temporale di BST-Insert è \(\Theta(h)\), che nel caso peggiore è \(O(N)\).

4. Esercizi e Riflessioni

Esercizio (dalla Professoressa): Riscrivere In-Order in-place

Testo: Sfruttando le procedure di ricerca del minimo e del successore, scrivere una versione in-place (iterativa) della visita In-Order di un BST, che non usi lo stack di ricorsione.

Soluzione (Aggiunta da AI):

L'idea è di partire dal minimo dell'albero e poi trovare ripetutamente il successore fino a esaurire tutti i nodi.


In-Order-Iterative(T)
  if T.root == NIL then
    return // Albero vuoto

  // 1. Trova il primo nodo da visitare (il minimo)
  current = BST-Min(T.root)
  
  // 2. Itera finché ci sono nodi da visitare
  while current != NIL do
    print(current.key) // Esamina il nodo corrente
    
    // 3. Trova il nodo successivo nell'ordine
    current = BST-Successor(current)

Questa procedura visita i nodi nell'ordine corretto. La sua complessità totale è la somma dei costi per trovare il minimo e poi N-1 chiamate a `BST-Successor`. Poiché ogni chiamata a `Successor` costa \(O(h)\), la complessità totale nel caso peggiore è \(O(N \cdot h)\). Questo è peggiore del \(\Theta(N)\) della versione ricorsiva. Tuttavia, è un utile esercizio per comprendere le relazioni tra i nodi in un BST.

5. Conclusioni

La lezione di oggi ha introdotto le operazioni fondamentali di ricerca e inserimento negli Alberi Binari di Ricerca.

Punti Chiave:

  • Le operazioni di ricerca (chiave specifica, minimo, massimo, successore, predecessore) e di inserimento in un BST hanno tutte una complessità temporale proporzionale all'altezza dell'albero, \(\Theta(h)\).
  • Poiché l'altezza di un BST può variare da \(\log N\) a \(N\), queste operazioni hanno una complessità nel caso peggiore di \(O(N)\).
  • L'inserimento in un BST avviene sempre aggiungendo il nuovo nodo come una foglia, preservando la proprietà del BST.
  • È possibile implementare le operazioni sia in modo ricorsivo che iterativo. Le versioni iterative sono generalmente più efficienti in termini di spazio (in-place).

La prossima lezione affronterà l'operazione più complessa: la cancellazione di un nodo da un BST.
