1. Introduzione: Oltre gli Algoritmi Basati su Confronti

La professoressa inizia la lezione (00:07) introducendo una nuova categoria di algoritmi di ordinamento. Finora abbiamo visto algoritmi come Insertion Sort, Merge Sort, HeapSort e QuickSort, che sono tutti basati sul confronto tra elementi per determinarne l'ordine relativo.

È stato dimostrato (e richiamato) che qualsiasi algoritmo di ordinamento che si basa esclusivamente su confronti tra elementi ha un limite inferiore di complessità di \(\Omega(N \log N)\) nel caso peggiore per ordinare \(N\) elementi.

Tuttavia, la professoressa pone la domanda: è possibile fare di meglio? La risposta è sì, ma solo se si introducono ipotesi aggiuntive sulla natura dell'input. Se non possiamo più basarci solo sui confronti, dobbiamo sfruttare altre proprietà dei dati da ordinare.

Gli algoritmi che vedremo oggi mirano a una complessità lineare (\(\Theta(N)\)) sotto queste specifiche ipotesi.

Riferimento Appunti Prof: La professoressa indica di fare riferimento agli appunti PDF "Nota 19 nov 2020 (2).pdf".

2. Counting Sort

Il primo algoritmo di ordinamento lineare presentato è il Counting Sort (00:32).

2.1. Idea e Ipotesi Fondamentali

Idea Principale (01:00): Counting Sort funziona contando il numero di occorrenze di ciascun elemento distintivo nell'array di input. Successivamente, utilizza queste informazioni sui conteggi per determinare direttamente le posizioni degli elementi nell'array ordinato di output.

Ipotesi Cruciale (07:00):

Gli elementi da ordinare devono essere interi compresi in un intervallo relativamente piccolo e noto: da 0 a \(K\) (inclusi), dove \(K\) è un intero. Se gli elementi fossero, ad esempio, da \(M\) a \(M+K\), si potrebbero traslare per ricondursi al caso 0 a \(K\).

Approfondimento (Aggiunto): Gestione Range Diversi da 0 a K

Se gli interi da ordinare sono in un range \([min\_val, max\_val]\), possiamo comunque usare Counting Sort. Il valore \(K\) dell'algoritmo diventerebbe \(max\_val - min\_val\). L'array dei conteggi `C` avrebbe dimensione \(K+1\). Quando si accede a `C`, si userebbe l'indice `A[j] - min_val`. Quando si costruisce l'array ordinato `B`, al valore letto da `C` andrebbe sommato `min_val` per ottenere il valore effettivo. La complessità rimarrebbe \(\Theta(N+K)\) dove \(K = max\_val - min\_val\).

2.2. Passaggi dell'Algoritmo Counting Sort

L'algoritmo procede come segue (spiegato dalla prof. tra 01:00 e 06:16, e illustrato negli appunti PDF a pagina 1-2):

Siano:

  • A: l'array di input di N elementi da ordinare.
  • B: l'array di output ordinato, della stessa dimensione di A.
  • C: un array ausiliario dei conteggi, di dimensione K+1 (dove K è il valore massimo in A).

Passaggi:

  1. Inizializzazione dell'Array dei Conteggi C (01:20):

    Si crea l'array C di dimensione K+1. Ogni elemento C[j] (per j da 0 a K) viene inizializzato a 0. Costo: \(\Theta(K)\).

    Array C (dim. K+1) dopo inizializzazione:

    Idx:012...K
    Val:000...0
  2. Conteggio delle Occorrenze (01:40):

    Si scorre l'array di input A. Per ogni elemento A[j] incontrato, si incrementa il contatore corrispondente in C. Cioè, C[A[j]] = C[A[j]] + 1. Al termine di questo passo, C[x] conterrà il numero di volte che il valore x compare in A. Costo: \(\Theta(N)\) (per scorrere A).

    Array C dopo conteggio occorrenze (esempio):

    Idx (Valore in A):0123...
    Conteggio:1241...

    (Significa che '0' compare 1 volta, '1' compare 2 volte, '2' compare 4 volte, ecc.)

  3. Calcolo delle Posizioni Finali (Somma Cumulativa) (02:22):

    Si modifica l'array C in modo che ogni C[j] contenga il numero di elementi nell'input A che sono minori o uguali a j. Questo si ottiene scorrendo C da j=1 a K e aggiornando C[j] = C[j] + C[j-1]. Ora, C[x] rappresenta l'indice (o la posizione finale +1, a seconda dell'indicizzazione) a cui l'ultimo elemento di valore x dovrebbe essere collocato nell'array ordinato B. Costo: \(\Theta(K)\) (per scorrere C).

    Array C dopo somma cumulativa (esempio da prima):

    Idx (Valore):0123...
    Conteggio Originale:1241...
    Valore Cumulativo:11+2=33+4=77+1=8...

    (Significa che ci sono 1 elemento <=0, 3 elementi <=1, 7 elementi <=2, 8 elementi <=3, ecc.)
    (Quindi, l'ultimo '0' andrà in B[1], l'ultimo '1' in B[3], l'ultimo '2' in B[7], l'ultimo '3' in B[8] - se B è 1-indexed)

    Approfondimento (Aggiunto): Perché C[x] indica la posizione finale?

    Dopo la somma cumulativa, C[x] ci dice quanti elementi in `A` sono minori o uguali a `x`. Se abbiamo, ad esempio, C[5]=12, significa che ci sono 12 elementi in `A` che sono \(\le 5\). Se stiamo usando un array di output `B` 1-indexed, l'ultimo degli elementi con valore 5 dovrà finire in posizione B[12]. Le posizioni da 1 a C[4] (se C[4] è, ad esempio, 9) saranno occupate da elementi \(\le 4\). Quindi, gli elementi con valore 5 occuperanno le posizioni da B[C[4]+1] a B[C[5]].

  4. Costruzione dell'Array Ordinato B (04:00):

    Si scorre l'array di input A dall'ultimo elemento al primo (cioè, per j da A.length decrescendo fino a 1). Questa scansione a ritroso è fondamentale per garantire la stabilità dell'algoritmo.

    Per ogni elemento A[j]:

    • L'elemento A[j] viene posizionato nell'array di output B all'indice dato da C[A[j]]. Cioè, B[C[A[j]]] = A[j].
    • Il valore C[A[j]] viene decrementato di 1: C[A[j]] = C[A[j]] - 1. Questo è necessario per assicurare che, se ci sono più occorrenze dello stesso valore A[j], vengano collocate in posizioni adiacenti e corrette in B, mantenendo il loro ordine relativo originale (stabilità).

    Costo: \(\Theta(N)\) (per scorrere A).

Al termine, l'array B conterrà gli elementi di A ordinati in modo non decrescente.

2.4. Pseudocodice di Counting Sort


Counting-Sort(A, B, K)
  // A: array di input (elementi da 0 a K)
  // B: array di output (stessa dimensione di A)
  // K: valore massimo in A
  
  // C: array ausiliario per i conteggi
  let C[0...K] be a new array

  // 1. Inizializza C a zero
  for i = 0 to K do
    C[i] = 0
  
  // 2. Conta le occorrenze di ogni elemento in A
  for j = 1 to A.length do // Assumendo A 1-indexed
    C[A[j]] = C[A[j]] + 1
  // Ora C[i] contiene il numero di elementi uguali a i
  
  // 3. Modifica C per contenere il numero di elementi minori o uguali a i
  for i = 1 to K do
    C[i] = C[i] + C[i-1]
  // Ora C[i] contiene la posizione finale (1-indexed) dell'ultimo elemento con valore i
  
  // 4. Costruisci l'array ordinato B
  for j = A.length downto 1 do // Scansiona A a ritroso per stabilità
    B[C[A[j]]] = A[j]
    C[A[j]] = C[A[j]] - 1
Nota sull'Indicizzazione (Aggiunto):

Nello pseudocodice sopra, ho assunto che l'array di input `A` e l'array di output `B` siano 1-indexed (indici da 1 a `A.length`), mentre l'array dei conteggi `C` è 0-indexed (indici da 0 a `K`) per mappare direttamente i valori degli elementi di `A` agli indici di `C`. Se `A` e `B` fossero 0-indexed (da 0 a `A.length-1`), gli accessi andrebbero leggermente modificati (es. `for j = 0 to A.length-1`, e `B[C[A[j]]-1] = A[j]` se `C` continua a rappresentare posizioni 1-indexed, oppure si adatta anche `C`). La logica di base rimane la stessa.

2.5. Complessità e Proprietà di Counting Sort

Complessità Temporale:

  • Passo 1 (Inizializzazione C): \(\Theta(K)\)
  • Passo 2 (Conteggio occorrenze): \(\Theta(N)\)
  • Passo 3 (Somma cumulativa): \(\Theta(K)\)
  • Passo 4 (Costruzione B): \(\Theta(N)\)

Complessità totale: \(\Theta(N+K)\).

Se \(K = O(N)\) (cioè, il range dei valori non è significativamente più grande del numero di elementi), allora la complessità diventa \(\Theta(N)\).

Complessità Spaziale:

Counting Sort richiede spazio ausiliario per:

  • L'array dei conteggi C di dimensione \(K+1\).
  • L'array di output B di dimensione \(N\).

Se consideriamo B come lo spazio di output richiesto, lo spazio ausiliario aggiuntivo è \(\Theta(K)\). Se \(K=O(N)\), lo spazio è \(\Theta(N)\). Counting Sort non è un algoritmo in-place.

Proprietà di Stabilità (05:05):

Counting Sort, implementato come descritto (con la scansione a ritroso nel passo 4), è un algoritmo stabile. Elementi con lo stesso valore in A mantengono il loro ordine relativo in B. Questo perché quando si incontrano elementi uguali durante la scansione a ritroso di A, l'elemento che compare prima in A (cioè più a destra) viene collocato in B in una posizione più a destra (indice C[valore] maggiore), e poi C[valore] viene decrementato. L'elemento uguale che compare dopo in A (più a sinistra) verrà collocato in B in una posizione più a sinistra (indice C[valore] ora più piccolo).

3. Radix Sort

Radix Sort è un altro algoritmo di ordinamento che può raggiungere complessità lineare sotto certe ipotesi (06:16).

3.1. Idea e Ipotesi

Idea Principale (06:35): Radix Sort ordina i numeri (o stringhe) processando le cifre (o caratteri) individualmente. La versione più comune, e quella spiegata, è **LSD Radix Sort** (Least Significant Digit first), che ordina gli elementi in base alla cifra meno significativa, poi in base alla successiva cifra meno significativa, e così via, fino alla cifra più significativa.

Ipotesi (07:00):

  • Gli input sono numeri (o più in generale, elementi le cui chiavi possono essere viste come sequenze di "cifre").
  • Tutti i numeri hanno al più d cifre. Se hanno meno di d cifre, si possono "paddare" con zeri iniziali.
  • Ogni cifra appartiene a un intervallo con K valori possibili (es. 0-9 per cifre decimali, quindi K=10; 0-1 per cifre binarie, K=2).

Algoritmo di Ordinamento Stabile Ausiliario (07:40): Radix Sort richiede un algoritmo di ordinamento ausiliario che sia stabile. Counting Sort è una scelta naturale e efficiente per questo, dato che le singole cifre hanno tipicamente un range K piccolo.

3.2. Passaggi dell'Algoritmo Radix Sort (LSD)


Radix-Sort(A, d)
  // A: array di input
  // d: numero massimo di cifre negli elementi di A
  
  for j = 1 to d do  // Itera dalla cifra meno significativa (j=1) alla più significativa (j=d)
    // Ordina l'array A in base alla j-esima cifra (da destra)
    // usando un algoritmo di ordinamento STABILE (es. Counting Sort sulla cifra j)
    Usa-Ordinamento-Stabile(A, cifra j)

La professoressa sottolinea (07:30) che si parte dalla cifra meno significativa (a destra) e si procede verso sinistra.

3.4. Correttezza di Radix Sort (Importanza della Stabilità)

La correttezza di Radix Sort (LSD) si dimostra per induzione sul numero di cifre j per cui l'array è stato ordinato.

Invariante di Ciclo: All'inizio dell'iterazione j (o dopo che l'ordinamento sulla (j-1)-esima cifra è stato completato), l'array A è ordinato rispetto alle j-1 cifre meno significative.

  • Caso Base (j=1): Prima del primo passo, l'array è ordinato rispetto a 0 cifre (banalmente vero). Dopo aver ordinato sulla 1° cifra (la meno significativa), l'array è ordinato rispetto a quella cifra.
  • Passo Induttivo: Assumiamo che l'array sia ordinato rispetto alle j-1 cifre meno significative. Ora ordiniamo l'array in base alla j-esima cifra usando un algoritmo stabile.
    • Consideriamo due numeri a e b.
      • Se la j-esima cifra di a è minore della j-esima cifra di b, allora a precederà b dopo l'ordinamento sulla j-esima cifra, indipendentemente dalle cifre meno significative (questo è corretto).
      • Se la j-esima cifra di a è maggiore della j-esima cifra di b, allora b precederà a (corretto).
      • Se la j-esima cifra di a è uguale alla j-esima cifra di b: Qui entra in gioco la stabilità. Poiché l'algoritmo di ordinamento sulla j-esima cifra è stabile, l'ordine relativo tra a e b (che era determinato dalle j-1 cifre meno significative, per ipotesi induttiva) viene preservato. Quindi, se a veniva prima di b (perché le sue prime j-1 cifre formavano un numero più piccolo), continuerà a venire prima.

Dopo d passaggi, l'array sarà ordinato rispetto a tutte le d cifre, e quindi completamente ordinato.

Crucialità della Stabilità: Se l'algoritmo di ordinamento intermedio non fosse stabile, l'ordine corretto stabilito dalle cifre meno significative potrebbe essere distrutto quando si ordinano cifre più significative uguali, portando a un risultato finale errato.

3.5. Complessità di Radix Sort

Siano:

  • N: numero di elementi da ordinare.
  • d: numero massimo di cifre per elemento.
  • K: numero di valori possibili per ogni cifra (es. K=10 per cifre decimali, K=256 per byte).

Se si usa Counting Sort per ordinare su ogni cifra (che ha K valori possibili), il costo di un passaggio di Counting Sort è \(\Theta(N+K)\).

Ci sono d passaggi (uno per ogni cifra).

Complessità totale di Radix Sort: \(\Theta(d \cdot (N+K))\).

Quando Radix Sort è Lineare in N? (08:30)

  • Se d è una costante (cioè il numero di cifre non dipende da N) e se K è dell'ordine di N (cioè \(K = O(N)\)) o costante, allora la complessità diventa \(\Theta(1 \cdot (N+N)) = \Theta(N)\) o \(\Theta(1 \cdot (N+1)) = \Theta(N)\).
  • Esempio: ordinare numeri interi di 32 bit (\(d \approx 4\) se si usano byte come "cifre", \(K=256\)). Se \(N\) è grande, \(N+K \approx N\), e la complessità è \(\Theta(d \cdot N)\), che è \(\Theta(N)\) se \(d\) è costante.

La professoressa discute (09:00) come la scelta di `d` e `K` (o la base `b` se le cifre sono in base `b`) sia importante. Se i numeri sono nell'intervallo da 0 a \(N^c - 1\) (per una costante c), allora \(d = \Theta(\log_b N^c) = \Theta(c \log_b N)\). Se si sceglie \(b=N\), allora \(d = \Theta(1)\) e \(K=N\), quindi \(\Theta(1(N+N)) = \Theta(N)\). Se si sceglie \(b=\text{costante}\) (es. 10), allora \(d=\Theta(\log N)\) e \(K=\text{costante}\), quindi \(\Theta(\log N (N+1)) = \Theta(N \log N)\).

La scelta ottimale della base per Radix Sort, quando si ordinano interi, è spesso correlata a N (es. \(b=N\)) per ottenere una complessità teorica lineare, ma in pratica si usano basi più piccole come potenze di 2 per efficienza con le operazioni a bit.

3.6. LSD (Least Significant Digit) vs MSD (Most Significant Digit) Radix Sort (Cenno)

La versione di Radix Sort discussa è LSD Radix Sort (si parte dalla cifra meno significativa).

Esiste anche MSD Radix Sort (si parte dalla cifra più significativa):

  • Si ordina prima in base alla cifra più significativa. Questo crea dei "bucket" di numeri che hanno la stessa prima cifra.
  • Poi si ordina ricorsivamente ogni bucket in base alla seconda cifra più significativa, e così via.
  • MSD Radix Sort non richiede che l'algoritmo di ordinamento intermedio sia stabile.
  • È concettualmente più simile a QuickSort (divide in bucket, poi ordina i bucket).
  • Può essere più complesso da implementare efficientemente.

La professoressa ha menzionato (08:00) che la versione LSD è quella standard e più semplice da implementare correttamente con Counting Sort.

4. Bucket Sort (Ordinamento a Secchielli)

Bucket Sort è un altro algoritmo di ordinamento che può avere prestazioni lineari sotto certe ipotesi (09:05).

4.1. Idea e Ipotesi

Idea Principale (09:08):

  1. Dividere l'intervallo di valori dei dati di input (tipicamente l'intervallo [0, 1)) in N sottointervalli di uguale ampiezza, chiamati "bucket" (secchielli).
  2. Distribuire gli N elementi dell'array di input nei rispettivi bucket.
  3. Ordinare gli elementi all'interno di ciascun bucket individualmente (spesso con un algoritmo semplice come Insertion Sort, dato che ci si aspetta che ogni bucket contenga pochi elementi).
  4. Concatenare gli elementi dei bucket ordinati (dal primo all'ultimo bucket) per produrre l'array finale ordinato.

Ipotesi Fondamentale (09:30):

Bucket Sort funziona bene (cioè, ha una complessità attesa lineare) se gli elementi dell'array di input sono estratti da una distribuzione di probabilità uniforme e indipendente sull'intervallo [0, 1). Questa ipotesi implica che ci si aspetta che gli elementi si distribuiscano in modo approssimativamente uniforme tra i bucket, con pochi elementi per bucket.

Approfondimento (Aggiunto): Cosa significa "Uniformemente e Indipendentemente Distribuiti"?
  • Uniformemente: Ogni sottointervallo di [0,1) di una certa lunghezza ha la stessa probabilità di contenere un elemento. Non ci sono "zone calde" dove gli elementi si concentrano di più.
  • Indipendentemente: Il valore di un elemento non influenza il valore di un altro elemento.

4.2. Passaggi dell'Algoritmo Bucket Sort

Sia A l'array di input di N elementi, con valori in \([0, 1)\).

  1. Creazione dei Bucket (09:50):

    Creare un array B di N liste concatenate (i bucket), inizialmente vuote. B[j] rappresenterà il j-esimo bucket. Costo: \(\Theta(N)\) (per creare N liste vuote).

  2. Distribuzione degli Elementi nei Bucket (10:00):

    Per ogni elemento A[i] nell'array di input:

    • Calcolare l'indice del bucket in cui A[i] deve essere inserito: indice_bucket = floor(N * A[i]). (Poiché \(0 \le A[i] < 1\), allora \(0 \le N \cdot A[i] < N\), quindi floor(N * A[i]) darà un indice da 0 a N-1).
    • Inserire A[i] nella lista concatenata B[indice_bucket]. L'inserimento in testa a una lista concatenata è \(\Theta(1)\).

    Costo totale: \(\Theta(N)\) (per scorrere A e fare N inserimenti \(\Theta(1)\)).

  3. Ordinamento dei Singoli Bucket (10:30):

    Per ogni bucket B[j] (per j da 0 a N-1):

    • Ordinare la lista concatenata B[j] utilizzando un algoritmo di ordinamento efficiente per piccole liste, come Insertion Sort.

    Il costo di questo passo dipende da quanti elementi finiscono in ciascun bucket. Vedremo l'analisi del caso atteso.

  4. Concatenazione dei Bucket Ordinati (10:45):

    Scorrere l'array dei bucket B da B[0] a B[N-1]. Per ogni bucket, prendere gli elementi (ora ordinati al suo interno) e accodarli sequenzialmente nell'array di output finale (o direttamente in A se si vuole tentare un in-place approssimativo, anche se più complesso). Costo: \(\Theta(N)\) (per scorrere tutti gli elementi una volta).

4.3. Esempio di Bucket Sort

La professoressa illustra un esempio (appunti PDF pagina 4, da 09:50).

Sia A = [0.3, 0.1, 0.8, 0.5, 0.78]. Qui N=5. Creiamo 5 bucket (liste), B[0]...B[4].

Distribuzione:

  • A[0]=0.3: indice = floor(5 * 0.3) = floor(1.5) = 1. Inserisci 0.3 in B[1].
  • A[1]=0.1: indice = floor(5 * 0.1) = floor(0.5) = 0. Inserisci 0.1 in B[0].
  • A[2]=0.8: indice = floor(5 * 0.8) = floor(4.0) = 4. Inserisci 0.8 in B[4].
  • A[3]=0.5: indice = floor(5 * 0.5) = floor(2.5) = 2. Inserisci 0.5 in B[2].
  • A[4]=0.78: indice = floor(5 * 0.78) = floor(3.9) = 3. Inserisci 0.78 in B[3].

Stato dei Bucket dopo distribuzione:

  • B[0]: [0.1]
  • B[1]: [0.3]
  • B[2]: [0.5]
  • B[3]: [0.78]
  • B[4]: [0.8]

(In questo esempio fortunato, ogni bucket ha al più un elemento).

Ordinamento Bucket: Ogni bucket è già ordinato (o l'ordinamento è banale).

Concatenazione: [0.1, 0.3, 0.5, 0.78, 0.8]. L'array è ordinato.

4.4. Complessità di Bucket Sort

Caso Atteso (con input uniformemente distribuito) (10:50):

Sia \(n_j\) il numero di elementi nel bucket \(B[j]\).

  • Passi 1, 2, 4 (creazione, distribuzione, concatenazione): \(\Theta(N)\) totali.
  • Passo 3 (ordinamento bucket): Il costo per ordinare il bucket \(B[j]\) con Insertion Sort è \(O(n_j^2)\). Il costo totale atteso per il passo 3 è \(E\left[\sum_{j=0}^{N-1} O(n_j^2)\right]\).
  • Si può dimostrare (analisi probabilistica non svolta in dettaglio) che se gli input sono uniformemente distribuiti, \(E\left[\sum_{j=0}^{N-1} n_j^2\right] = \Theta(N)\). L'intuizione è che \(n_j\) è piccolo per la maggior parte dei bucket. Il valore atteso di \(n_j\) è 1. \(E[n_j^2] = E[n_j]^2 + Var(n_j)\). Per la distribuzione uniforme, la varianza è piccola e la somma dei quadrati rimane lineare.

Quindi, la complessità totale attesa di Bucket Sort è \(\Theta(N)\).

Caso Peggiore (11:30):

Se tutti gli \(N\) elementi di input cadono nello stesso bucket (es. sono tutti molto vicini tra loro o l'ipotesi di uniformità non vale), allora:

  • Un solo bucket conterrà \(N\) elementi.
  • Ordinare quel bucket con Insertion Sort costerà \(\Theta(N^2)\).
  • Gli altri passi rimangono \(\Theta(N)\).

Quindi, la complessità nel caso peggiore di Bucket Sort è \(\Theta(N^2)\).

Come gestire il caso peggiore: Se si teme il caso peggiore, si può usare un algoritmo di ordinamento \(\Theta(N \log N)\) (come Merge Sort o HeapSort) per ordinare i bucket che diventano troppo grandi, invece di Insertion Sort. Questo porterebbe la complessità del caso peggiore a \(\Theta(N \log N)\) mantenendo il \(\Theta(N)\) atteso.

5. Conclusioni sugli Algoritmi di Ordinamento Lineare

La professoressa conclude riassumendo (12:20):

  • Counting Sort: \(\Theta(N+K)\). Lineare se \(K=O(N)\). Stabile. Non in-place. Richiede interi in un range limitato.
  • Radix Sort: \(\Theta(d(N+K))\). Lineare se \(d\) è costante e \(K=O(N)\) (o costante). Stabile (se usa un algoritmo stabile internamente). Non in-place. Richiede numeri con un numero fisso di cifre (o paddabili).
  • Bucket Sort: \(\Theta(N)\) nel caso atteso (con input uniformemente distribuiti). \(\Theta(N^2)\) nel caso peggiore (se si usa Insertion Sort per i bucket). Tipicamente non stabile (dipende dall'ordinamento dei bucket e dall'inserimento). Richiede input da una distribuzione nota (tipicamente uniforme su [0,1)).

Questi algoritmi superano il limite \(\Omega(N \log N)\) perché non si basano solo su confronti, ma sfruttano informazioni sulla struttura o distribuzione dei dati (valori interi in un range, numero di cifre, distribuzione uniforme).

Esercizio Suggerito (Aggiunto): Implementazione di Counting Sort per Caratteri

Testo: Scrivere una procedura CountingSortChars(A, B) che ordina un array A di caratteri (es. lettere minuscole 'a'-'z') e mette il risultato in B, utilizzando Counting Sort. Assumere che i caratteri possano essere mappati a interi (es. 'a'=0, 'b'=1, ..., 'z'=25).

Svolgimento (Idea):

  1. Determinare il valore di K. Se sono solo lettere minuscole, K=25 (per indici 0-25).
  2. L'array dei conteggi `C` avrà dimensione 26.
  3. Nel passo di conteggio occorrenze, per un carattere `char_A` in `A`, si incrementerà `C[valore_intero(char_A)]`.
  4. Nel passo di costruzione di `B`, quando si posiziona `char_A`, lo si mette in `B[C[valore_intero(char_A)]]`.

CountingSortChars(A, B) // A, B array di caratteri, K=25 (per 'a' to 'z')
  let C[0...25] be a new array

  for i = 0 to 25 do
    C[i] = 0
  
  for j = 0 to A.length-1 do // Assumendo A 0-indexed
    // char_to_int converte 'a'->0, 'b'->1, ...
    C[char_to_int(A[j])] = C[char_to_int(A[j])] + 1
  
  for i = 1 to 25 do
    C[i] = C[i] + C[i-1]
  
  for j = A.length-1 downto 0 do // Scansiona A a ritroso
    // int_to_char converte 0->'a', 1->'b', ... (non serve per B, A[j] è già char)
    // C[valore] dà la posizione 1-indexed, quindi B è 0-indexed
    B[C[char_to_int(A[j])] - 1] = A[j] 
    C[char_to_int(A[j])] = C[char_to_int(A[j])] - 1
Esercizio Suggerito (Aggiunto): Quando Radix Sort è meglio di Counting Sort?

Testo: Considera di dover ordinare N interi. Se sai che il valore massimo K è molto grande, ad esempio \(K \approx N^3\), ma sai anche che i numeri sono rappresentati con un numero di cifre \(d = \Theta(\log N)\) in una certa base B (dove B è piccolo, es. B=10 o B=256). Quale algoritmo tra Counting Sort e Radix Sort (usando Counting Sort per le cifre) sarebbe asintoticamente migliore?

Svolgimento (Idea):

  • Counting Sort: Complessità \(\Theta(N+K)\). Se \(K \approx N^3\), allora \(\Theta(N+N^3) = \Theta(N^3)\).
  • Radix Sort: Complessità \(\Theta(d(N+B))\).
    • \(d = \Theta(\log N)\).
    • Se B è una costante piccola (es. 10 o 256), allora \(N+B \approx N\).
    • La complessità di Radix Sort diventa \(\Theta(\log N \cdot N) = \Theta(N \log N)\).

In questo scenario, Radix Sort con \(\Theta(N \log N)\) è asintoticamente molto migliore di Counting Sort con \(\Theta(N^3)\).
