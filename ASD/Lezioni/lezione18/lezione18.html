1. Introduzione e Recap: Indirizzamento Aperto

La professoressa inizia la lezione riprendendo i concetti dell'hashing con indirizzamento aperto (open addressing), presentati nella lezione precedente. Fa riferimento agli appunti PDF "Nota 30 nov 2020 (2).pdf".

Recap dei Punti Chiave dell'Indirizzamento Aperto:

  • Tutti gli elementi sono memorizzati direttamente nell'array della tabella di hash (dimensione M).
  • Non ci sono liste concatenate o strutture dati esterne, risparmiando spazio.
  • Quando si inserisce un elemento e si trova lo slot occupato (collisione), si utilizza una sequenza di ispezione (probing) per trovare uno slot libero.
  • La funzione di hash dipende sia dalla chiave che dal tentativo di ispezione: \(h(k, i)\), dove \(i\) va da 0 a M-1.
  • La sequenza di ispezione \(\langle h(k,0), h(k,1), \dots, h(k,M-1) \rangle\) deve essere una permutazione degli indici \((0, \dots, M-1)\) per garantire che tutti gli slot vengano visitati.
  • La cancellazione è complessa e richiede un marcatore speciale DELETED per non interrompere le catene di ispezione durante la ricerca.

2. Operazioni nell'Indirizzamento Aperto: Pseudocodice e Analisi

La professoressa analizza in dettaglio lo pseudocodice delle operazioni di inserimento, ricerca e cancellazione, discutendone la logica e la correttezza.

2.1. Inserimento (Hash-Insert-Open)

La procedura Hash-Insert-Open(T, x) (dove x è l'intero oggetto da inserire) cerca di inserire l'oggetto x nella tabella T.


Hash-Insert-Open(T, x, h)
  M = T.length
  i = 0  // Indice del tentativo di ispezione
  
  repeat
    j = h(x.key, i) // Calcola la posizione per il tentativo i
    
    // Se lo slot è libero (NIL) o precedentemente cancellato (DELETED), inserisci.
    if T[j] == NIL or T[j] == DELETED then
      T[j] = x
      return j // Restituisci la posizione di inserimento
    else
      i = i + 1 // Altrimenti, passa al tentativo successivo
      
  until i == M // Se ho provato tutte le M posizioni
  
  // Se il ciclo termina, la tabella è piena
  error "Hash table overflow"

Logica:

  1. Si inizializza il contatore dei tentativi i a 0.
  2. Si entra in un ciclo che si ripeterà al massimo M volte.
  3. Ad ogni iterazione, si calcola l'indice j usando la funzione di hash con il tentativo corrente i.
  4. Se la cella T[j] è libera (NIL) o contiene un elemento cancellato (DELETED), si inserisce l'oggetto x in quella posizione e si termina con successo.
  5. Se la cella è occupata, si incrementa i e si continua con il prossimo tentativo.
  6. Se il ciclo completa M iterazioni senza trovare uno slot libero, significa che la tabella è piena e si solleva un errore di overflow.

2.2. Ricerca (Hash-Search-Open)

La procedura Hash-Search-Open(T, k_search) cerca una chiave k_search nella tabella T.


Hash-Search-Open(T, k_search, h)
  i = 0
  
  repeat
    j = h(k_search, i)
    
    // Se trovo l'elemento desiderato, restituisco il suo indice
    if T[j] != NIL and T[j] != DELETED and T[j].key == k_search then
        return j

    i = i + 1
    
  // La ricerca termina se trovo una cella NIL (che interrompe la catena)
  // o se ho scandito tutta la tabella senza successo.
  until T[j] == NIL or i == M 
  
  return -1 // o un valore speciale per "non trovato"
Approfondimento sulla Logica della Ricerca (dal dialogo della prof.ssa):

La professoressa chiarisce un punto importante: la ricerca deve continuare anche se incontra una cella DELETED. La catena di ispezione si interrompe solo quando si trova una cella NIL (che non è mai stata occupata da quando la catena è iniziata) o quando si è esaurita l'intera sequenza di ispezione (i=M).

Una versione leggermente diversa ma equivalente dello pseudocodice (più simile a quella degli appunti PDF) potrebbe essere:


// Versione alternativa di Hash-Search-Open
Hash-Search-Open(T, k_search, h)
  i = 0
  j = h(k_search, i)

  // Continua finché non trovo una cella vuota (NIL) E
  // la cella corrente non contiene la chiave cercata.
  while (T[j] != NIL and T[j].key != k_search) do
    i = i + 1
    if i == M then return -1 // Tutta la tabella controllata
    j = h(k_search, i)
  
  if T[j].key == k_search then
    return j
  else // Se T[j] è NIL (o non è la chiave dopo i=M-1)
    return -1

La professoressa, nella sua spiegazione orale, evidenzia la necessità di gestire il caso in cui `T[j]` sia `NIL` o `DELETED` prima di tentare di accedere a `.key`, per evitare errori. Lo pseudocodice corretto deve tenere conto di questo. L'essenza è che la ricerca prosegue su celle `DELETED` e si ferma su `NIL`.

2.3. Cancellazione (Hash-Delete-Open)

La cancellazione è semplice una volta che si è trovata la posizione dell'elemento da cancellare.


Hash-Delete-Open(T, x, h)
  // Cerca l'indice dell'oggetto x (o della sua chiave x.key)
  j = Hash-Search-Open(T, x.key, h) 

  // Se l'elemento è stato trovato (j non è un valore di errore)
  if j != -1 then // o j != NIL
    T[j] = DELETED

La procedura si basa sulla ricerca per localizzare l'elemento e, se trovato, lo sovrascrive con il marcatore speciale DELETED.

2.4. Complessità delle Operazioni (Caso Peggiore)

Nel caso peggiore, ogni operazione (inserimento, ricerca, cancellazione) potrebbe dover ispezionare tutti gli M slot della tabella.

Ad esempio, se sto inserendo un elemento in una tabella quasi piena, potrei dover provare quasi tutte le posizioni. Se sto cercando un elemento che non c'è, e la tabella è piena (o piena di marcatori `DELETED`), dovrò scandire tutti gli M slot.

Pertanto, la complessità nel caso peggiore per tutte e tre le operazioni è \(\Theta(M)\) (o \(\Theta(N)\) se \(M\) è proporzionale a \(N\)).

3. Analisi del Caso Medio

La professoressa discute l'analisi del caso medio, che è più interessante e mostra la vera efficacia dell'hashing. Questa analisi si basa su un'ipotesi forte.

3.1. Ipotesi di Hashing Uniforme

L'analisi del caso medio per l'indirizzamento aperto si basa sull'Ipotesi di Hashing Uniforme. Questa ipotesi è più forte della "semplice" ipotesi uniforme vista per il chaining.

Definizione: Si assume che, per ogni chiave k, la sua sequenza di ispezione \(\langle h(k,0), h(k,1), \dots \rangle\) sia una delle M! possibili permutazioni degli indici \((0, \dots, M-1)\), scelta in modo equiprobabile.

Conseguenze:

  • Ogni possibile sequenza di ispezione ha probabilità \(1/M!\).
  • Questa è un'ipotesi molto forte e difficile da realizzare in pratica. Nessuna delle tecniche di ispezione viste (lineare, quadratica, hashing doppio) soddisfa pienamente questa ipotesi.
  • L'hashing doppio è la tecnica che più si avvicina a questo comportamento ideale.

3.2. Teorema sul Costo Medio (Senza Dimostrazione)

Sotto l'ipotesi di hashing uniforme, si può dimostrare il seguente teorema sul costo atteso delle operazioni.

Dato una tabella di hash con indirizzamento aperto e un fattore di carico \(\alpha = N/M < 1\), il numero atteso di ispezioni per un'operazione di inserimento (o una ricerca con esito negativo) è al più:

\( \frac{1}{1 - \alpha} \)

Interpretazione del Risultato:

  • Questo risultato mostra che il costo atteso dipende criticamente dal fattore di carico \(\alpha\).
  • Se la tabella è quasi vuota (\(\alpha \to 0\)), il numero di ispezioni tende a 1.
  • Se la tabella è piena a metà (\(\alpha = 0.5\)), il numero atteso di ispezioni è \(1/(1-0.5) = 2\).
  • Se la tabella è piena al 90% (\(\alpha = 0.9\)), il numero atteso è \(1/(1-0.9) = 1/0.1 = 10\).
  • Man mano che \(\alpha\) si avvicina a 1, il costo atteso tende all'infinito.

Questo conferma l'importanza di mantenere il fattore di carico basso nelle tabelle di hash con indirizzamento aperto. Se \(\alpha\) è una costante mantenuta bassa (es. \(\le 0.75\)), il costo atteso rimane costante.

4. Tecniche di Ispezione in Pratica (Ripasso e Confronto)

La professoressa rivede brevemente le tre tecniche di ispezione discusse, mettendole a confronto.

4.1. Ispezione Lineare e Clustering Primario

Formula: \( h(k, i) = (h'(k) + i) \pmod{M} \)

  • Non soddisfa l'hashing uniforme: Genera solo M diverse sequenze di ispezione, non M!.
  • Problema: Clustering primario. I blocchi di celle occupate tendono a crescere, degradando le performance.

4.2. Ispezione Quadratica

Formula: \( h(k, i) = (h'(k) + c_1 i + c_2 i^2) \pmod{M} \)

  • Mitiga il clustering primario: I salti non sono più contigui.
  • Non soddisfa l'hashing uniforme: Produce solo M sequenze diverse.
  • Problema: Clustering secondario. Se due chiavi diverse hanno lo stesso hash iniziale (\(h'(k_1) = h'(k_2)\)), genereranno la stessa identica sequenza di ispezione.

4.3. Hashing Doppio

Formula: \( h(k, i) = (h_1(k) + i \cdot h_2(k)) \pmod{M} \)

  • La tecnica migliore in pratica.
  • Non soddisfa pienamente l'hashing uniforme, ma ci si avvicina molto: Genera circa \(M^2\) diverse sequenze di ispezione, un numero molto più grande di M, che porta a una migliore distribuzione.
  • Risolve il clustering secondario: Chiavi con lo stesso \(h_1\) avranno probabilmente \(h_2\) diversi, e quindi sequenze di ispezione diverse.
  • Requisito: \(h_2(k)\) deve essere sempre coprimo con \(M\). Questo si ottiene facilmente scegliendo \(M\) come numero primo e \(h_2\) che produca valori tra 1 e M-1.

5. Esercizio: Hashing con Ispezione Lineare (Esempio dei Comuni)

La professoressa svolge un esercizio pratico per illustrare il clustering primario con ispezione lineare.

Setup:

  • Tabella T di dimensione M=21 (una per ogni lettera dell'alfabeto italiano).
  • Funzione di hash \(h'(comune) = \text{indice dell'iniziale}\).

Esecuzione:

  1. Inserisci Bologna: h'("Bologna") \(\to\) 1. T[1] = Bologna.
  2. Inserisci Bergamo: h'("Bergamo") \(\to\) 1 (collisione). Ispezione lineare: prova T[2], è libero. T[2] = Bergamo.
  3. Inserisci Brescia: h'("Brescia") \(\to\) 1 (collisione). Prova T[2] (occupato). Prova T[3], è libero. T[3] = Brescia.
    Si è formato un cluster [Bologna, Bergamo, Brescia].
  4. Inserisci Ancona: h'("Ancona") \(\to\) 0. T[0] = Ancona.
  5. Inserisci Nova Milanese: h'("Nova Milanese") \(\to\) 13 (N). T[13] = Nova Milanese.

La professoressa evidenzia che con la scansione lineare, se due chiavi \(x\) e \(y\) partono da posizioni diverse (\(h'(x) \neq h'(y)\)), le loro sequenze di ispezione possono comunque "convergere" e diventare identiche da un certo punto in poi se una finisce nel percorso di scansione dell'altra. Questo è il problema del clustering primario.

6. Esercizi per Casa

La professoressa assegna esercizi di verifica sulle funzioni di hash. L'obiettivo è determinare se una data funzione di hash è "buona" o meno.

Esercizio (dalla Professoressa):

Analizzare le seguenti funzioni di hash per chiavi intere e una tabella di dimensione M, determinando se sono valide e/o ben distribuite.

  1. \(h_1(k) = (k \pmod M) + 3\).
    Soluzione (discussa in aula): Non è valida. Il risultato può essere > M-1 (es. se \(k \pmod M = M-1\), il risultato è M+2), andando fuori dalla tabella.
  2. \(h_2(k) = (k \pmod{M-3}) + 3\).
    Soluzione (discussa in aula): È valida (mappa sempre in [3, M-1]), ma non è buona perché non è suriettiva. Le posizioni 0, 1, 2 non vengono mai utilizzate.
  3. \(h_3(k) = (2 \cdot k) \pmod M\).
    Soluzione (discussa in aula): Se M è una potenza di 2 (o anche solo un numero pari, come M=2), questa funzione userà solo le posizioni pari, non essendo suriettiva.
  4. \(h_4(k) = \max(N-M, k) \pmod M\). (N è una costante fissata).
    Soluzione (discussa in aula): Non è buona. Se la maggior parte delle chiavi `k` è più piccola di `N-M`, la funzione restituirà quasi sempre `(N-M) mod M`, concentrando molte chiavi su un unico slot.
  5. \(h_5(k) = ((k \pmod M) + 125) \pmod M\).
    Soluzione (discussa in aula): Questa è fondamentalmente equivalente a `k mod M`, ma con uno shift fisso di 125 posizioni. È buona tanto quanto il metodo della divisione base. È valida e suriettiva. Sarà ben distribuita se M è un buon numero primo.

7. Conclusioni

La lezione ha fornito una panoramica completa delle operazioni e dell'analisi delle tabelle di hash con indirizzamento aperto.

Punti Chiave da Ricordare:

  • Le operazioni di inserimento, ricerca e cancellazione devono gestire attentamente i tre stati delle celle: **Occupato, NIL, DELETED**.
  • Il costo nel caso peggiore è \(\Theta(M)\), ma il costo atteso (sotto ipotesi di hashing uniforme) è \(\Theta(1/(1-\alpha))\), rendendo cruciale mantenere basso il fattore di carico \(\alpha\).
  • Le tecniche di ispezione (lineare, quadratica, hashing doppio) hanno diversi livelli di efficacia nel combattere il clustering, con l'hashing doppio che offre le migliori garanzie pratiche.
  • La scelta di una buona funzione di hash e dei parametri (come M e le costanti di ispezione) è fondamentale per le prestazioni del sistema.

La professoressa conclude annunciando che l'argomento successivo saranno gli alberi binari di ricerca (BST).
