1. Testo del Problema

Sia A un vettore di interi. Si consideri il problema di decidere se esistono due interi distinti che occorrono in A lo stesso numero di volte (devono entrambi occorrere in A almeno una volta).

Si richiede di:

  1. Descrivere una procedura efficiente per risolvere il problema.
  2. Fornire lo pseudo-codice della procedura.
  3. Dimostrare la correttezza e valutare la complessità della procedura proposta.

2. Descrizione della Procedura

La strategia proposta si basa sull'idea di trasformare il problema in un problema più semplice e noto: trovare duplicati in un insieme di conteggi. Per raggiungere questo obiettivo, la procedura si articola in tre fasi principali, utilizzando l'ordinamento come strumento chiave.

2.1. Fase 1: Raggruppamento (Ordinamento)

Il primo passo consiste nell'ordinare il vettore di input A. Utilizzando un algoritmo di ordinamento efficiente come HeapSort o MergeSort, tutti gli elementi identici vengono raggruppati in blocchi contigui. Questo rende il successivo conteggio delle loro occorrenze un'operazione semplice e lineare.

Esempio: A = [4, 1, 8, 4, 1, 1, 4] diventa A_ordinato = [1, 1, 1, 4, 4, 4, 8]

1 1 1 4 4 4 8

2.2. Fase 2: Conteggio delle Frequenze

Questa fase determina la frequenza di ogni numero unico e memorizza questi conteggi in un nuovo array. Per avere un controllo esplicito sulla memoria, questa fase viene eseguita in due passate:

  1. Passata 2.1 (Calcolo di U): Si esegue una prima scansione lineare dell'array A (ora ordinato) per contare il numero di elementi unici, che chiameremo U. Questo valore è necessario per sapere la dimensione esatta dell'array che dovrà contenere le frequenze.
  2. Passata 2.2 (Riempimento dell'Array Frequenze): Dopo aver allocato un array Frequenze di dimensione U, si esegue una seconda scansione di A. Per ogni blocco di elementi contigui e identici, se ne conta la dimensione (che è la loro frequenza) e si memorizza questo valore nell'array Frequenze.

Dall'esempio precedente (A_ordinato = [1, 1, 1, 4, 4, 4, 8]):

  • Passata 2.1: U = 3 (gli elementi unici sono 1, 4, 8).
  • Passata 2.2:
    • Blocco di '1': lunghezza 3.
    • Blocco di '4': lunghezza 3.
    • Blocco di '8': lunghezza 1.
    L'array Frequenze diventa [3, 3, 1].

2.3. Fase 3: Rilevamento di Duplicati nelle Frequenze

A questo punto, il problema originale è stato ridotto a determinare se l'array Frequenze contiene valori duplicati. Per risolvere questo sottoproblema in modo efficiente:

  1. Si ordina l'array Frequenze. Dopo l'ordinamento, eventuali frequenze duplicate si troveranno necessariamente in posizioni adiacenti.
  2. Si esegue un'ultima scansione lineare di Frequenze per verificare se Frequenze[k] == Frequenze[k-1] per qualche k.
  3. Se si trova una tale coppia, l'algoritmo termina restituendo `true`. Altrimenti, se si completa la scansione senza trovare duplicati, si restituisce `false`.

Dall'esempio precedente (Frequenze = [3, 3, 1]):

  • Ordinando Frequenze si ottiene [1, 3, 3].
  • Scansionando, si troverà che Frequenze[2] == Frequenze[1].
  • L'algoritmo restituisce `true`.

3. Pseudo-codice


// Funzione principale che risolve il problema.
// Input: A, un vettore di N interi.
// Output: true se esistono due interi distinti con la stessa frequenza, altrimenti false.

TrovaFrequenzeDuplicate(A)
  N = A.length
  // Caso base: se ci sono meno di 2 elementi, è impossibile avere due interi distinti.
  if N < 2 then
    return false

  // --- FASE 1: Ordinamento dell'Array di Input ---
  MergeSort(A, 0, N - 1) // Complessità: Θ(N log N)

  // --- FASE 2.1: Prima Passata - Contare il numero di elementi unici (U) ---
  if N > 0 then
    U = 1
  else
    U = 0
  
  for i = 1 to N - 1 do
    if A[i] != A[i-1] then
      U = U + 1
  
  // Se ci sono meno di 2 elementi unici, non possono esistere due interi *distinti*
  if U < 2 then
    return false

  // --- FASE 2.2: Allocazione e Riempimento dell'Array delle Frequenze ---
  Frequenze = New_Array(U)
  i = 0
  freq_index = 0
  while i < N do
    j = i // Inizio di un blocco di elementi uguali
    while j < N and A[j] == A[i] do
      j = j + 1
    
    conteggio = j - i // Lunghezza del blocco
    Frequenze[freq_index] = conteggio
    freq_index = freq_index + 1
    
    i = j // Passa al blocco successivo
  
  // --- FASE 3: Rilevamento di Frequenze Duplicate ---
  MergeSort(Frequenze, 0, U - 1) // Complessità: Θ(U log U)
  
  // Scansiona l'array ordinato Frequenze per trovare duplicati adiacenti.
  for k = 1 to U - 1 do
    if Frequenze[k] == Frequenze[k-1] then
      return true // Trovato!
      
  return false // Nessuna frequenza duplicata trovata

4. Analisi di Correttezza e Complessità

4.1. Correttezza

  1. Fase 1 (Ordinamento di A): Questo passo è corretto perché raggruppa elementi identici in modo contiguo senza alterare l'insieme di valori o le loro frequenze, ma solo le posizioni.
  2. Fase 2 (Conteggio):
    • La Passata 2.1 calcola correttamente `U` (numero di elementi unici). In un array ordinato, ogni nuovo valore unico è segnalato da un cambio rispetto all'elemento precedente (`A[i] != A[i-1]`).
    • La Passata 2.2 è corretta. Il ciclo `while` esterno (indicizzato da `i`) assicura che ogni blocco di elementi uguali venga processato esattamente una volta. L'indice `i` viene fatto avanzare a `j` dopo ogni blocco, evitando di ri-contare elementi. Il ciclo interno (indicizzato da `j`) determina correttamente la fine del blocco corrente. La differenza `j-i` calcola esattamente la frequenza. Al termine, l'array `Frequenze` conterrà le frequenze di tutti gli `U` interi unici di `A`.
  3. Fase 3 (Rilevamento): Il problema è stato correttamente ridotto a trovare duplicati nel vettore `Frequenze`. L'ordinamento di `Frequenze` è una strategia corretta perché garantisce che, se esistono duplicati, almeno una coppia di valori identici diventerà adiacente. La scansione finale che confronta `Frequenze[k]` con `Frequenze[k-1]` è quindi sufficiente per rilevare la presenza di qualsiasi duplicato. Se restituisce `true`, ha trovato la prova richiesta. Se restituisce `false`, ha escluso la possibilità di duplicati.

L'algoritmo risolve correttamente il problema.

4.2. Complessità Temporale

La complessità totale è la somma dei costi delle varie fasi:

  • Fase 1 (MergeSort su A): L'ordinamento di \(N\) elementi ha una complessità di \(\Theta(N \log N)\).
  • Fase 2.1 (Calcolo di U): Una singola scansione lineare di A. Costo: \(\Theta(N)\).
  • Fase 2.2 (Riempimento di Frequenze): Anche questa è una singola scansione lineare di A. Costo: \(\Theta(N)\).
  • Fase 3 (Rilevamento Duplicati):
    • Ordinamento di Frequenze (di dimensione U): \(\Theta(U \log U)\).
    • Scansione finale per duplicati adiacenti: \(\Theta(U)\).

La complessità totale è \(\Theta(N \log N) + \Theta(N) + \Theta(N) + \Theta(U \log U) + \Theta(U)\).

Poiché \(U \le N\), il termine \(\Theta(U \log U)\) è maggiorato da \(O(N \log N)\).

Il termine dominante dell'intera espressione è quindi \(\mathbf{\Theta(N \log N)}\).

4.3. Complessità Spaziale

  • L'algoritmo di ordinamento MergeSort richiede spazio ausiliario proporzionale all'input, quindi \(\Theta(N)\).
    Nota: Se si utilizzasse HeapSort (che è in-place), lo spazio per l'ordinamento si ridurrebbe a \(\Theta(1)\) (o \(\Theta(\log N)\) per lo stack della versione ricorsiva, se usata).
  • L'array ausiliario Frequenze ha dimensione \(U\). Nel caso peggiore, tutti gli elementi sono distinti, quindi \(U=N\). Lo spazio richiesto è \(\Theta(U)\), che è \(O(N)\).

La complessità spaziale totale è dominata o da MergeSort o dall'array Frequenze, risultando in \(\mathbf{O(N)}\).

5. Approfondimenti e Soluzioni Alternative

Approfondimento: Soluzione alternativa con Tabelle di Hash

Un approccio alternativo, spesso più efficiente in pratica sebbene con una complessità nel caso peggiore potenzialmente superiore, utilizza le tabelle di hash.

Idea della Soluzione:

  1. Fase 1: Costruire una mappa delle frequenze.
    • Si scorre l'array di input A.
    • Per ogni elemento A[i], lo si usa come chiave in una tabella di hash `MappaFrequenze`.
    • Se la chiave `A[i]` è già presente, se ne incrementa il valore (il conteggio). Altrimenti, la si inserisce con conteggio 1.
    Questo passo ha un costo atteso di \(\Theta(N)\) se si usa una buona funzione di hash.
  2. Fase 2: Trovare duplicati tra i conteggi.
    • Si estraggono tutti i valori (i conteggi) dalla `MappaFrequenze` in un nuovo array (o lista).
    • Si usa una seconda tabella di hash (`MappaConteggi`) per verificare se un conteggio è già stato visto. Si scorre l'array dei conteggi: se un conteggio è già presente nella `MappaConteggi`, si è trovato un duplicato e si restituisce `true`. Altrimenti, lo si inserisce.
    Anche questo passo ha un costo atteso di \(\Theta(U)\), dove U è il numero di elementi unici.

Complessità della Soluzione con Hash:

  • Tempo Atteso: \(\Theta(N) + \Theta(U) = \Theta(N)\).
  • Tempo nel Caso Peggiore: Se la tabella di hash degenera, il costo può diventare \(\Theta(N^2)\).
  • Spazio: Richiede due tabelle di hash, che nel caso peggiore possono occupare spazio \(\Theta(N)\) (per `MappaFrequenze`) e \(\Theta(U)\) (per `MappaConteggi`), quindi \(\Theta(N)\) in totale.

Questo approccio è asintoticamente più veloce nel caso medio ma potenzialmente più lento nel caso peggiore rispetto alla soluzione basata su ordinamento.

Approfondimento: Si può risolvere il problema con complessità spaziale \(\Theta(1)\)?

No, non con un algoritmo di ordinamento generale. Il problema richiede di memorizzare informazioni sui conteggi di un numero potenzialmente elevato di elementi unici. Senza fare ipotesi aggiuntive sul range dei valori (che permetterebbero di usare Counting Sort), non è noto un algoritmo che risolva questo problema in tempo \(O(N \log N)\) e spazio \(\Theta(1)\). La soluzione basata su ordinamento con HeapSort si avvicina, richiedendo \(\Theta(N \log N)\) in tempo e \(\Theta(U)\) (fino a \(O(N)\)) in spazio per l'array delle frequenze.
