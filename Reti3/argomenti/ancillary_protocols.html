1. ARP (Address Resolution Protocol)

ARP è un protocollo fondamentale che risolve un problema chiave: come tradurre un indirizzo logico di livello 3 (indirizzo IP) in un indirizzo fisico di livello 2 (indirizzo MAC) all'interno della stessa rete locale (LAN).

Perché è Necessario ARP?

Quando un host A vuole inviare un pacchetto IP a un host B sulla stessa LAN, deve incapsulare il pacchetto IP in un frame di livello 2 (es. Ethernet). L'header del frame Ethernet richiede l'indirizzo MAC di destinazione. L'host A conosce l'indirizzo IP di B, ma non necessariamente il suo indirizzo MAC. ARP serve a scoprire questo indirizzo MAC.

Funzionamento di ARP

  1. Controllo della Cache ARP: L'host A controlla la sua tabella ARP (una cache locale) per vedere se ha già una mappatura per l'indirizzo IP di B.
  2. ARP Request (Broadcast): Se non trova una mappatura, A invia un ARP Request in broadcast sulla LAN. Questo messaggio chiede: "Chi ha l'indirizzo IP 192.168.1.10? Per favore, dimmi il tuo indirizzo MAC."
  3. ARP Reply (Unicast): L'host B, riconoscendo il proprio IP nella richiesta, risponde direttamente ad A con un ARP Reply in unicast. Questo messaggio contiene il suo indirizzo MAC.
  4. Aggiornamento della Cache: L'host A riceve la risposta, aggiorna la sua tabella ARP con la mappatura IP-MAC e può ora inviare il frame Ethernet all'indirizzo MAC di B.

ARP e Routing

Se l'host di destinazione B si trova su una rete diversa, l'host A non userà ARP per trovare il MAC di B, ma per trovare l'indirizzo MAC del suo router di default (gateway). Il pacchetto IP verrà quindi incapsulato in un frame con l'indirizzo MAC del router come destinazione.

Punti Chiave per l'Esame:
  • ARP opera solo all'interno di una LAN.
  • Una richiesta ARP è inviata in broadcast, una risposta ARP è inviata in unicast.
  • Se un host deve inviare un pacchetto a una rete esterna, usa ARP per trovare il MAC del gateway, non della destinazione finale.
  • Proxy ARP: Un router può rispondere a richieste ARP per conto di altri host, rendendo "trasparente" la presenza di sottoreti.
  • Vulnerabilità (ARP Poisoning/Spoofing): Poiché ARP è un protocollo "trusting", un attaccante sulla stessa LAN può inviare risposte ARP false per dirottare il traffico (attacco Man-in-the-Middle).

2. DHCP (Dynamic Host Configuration Protocol)

DHCP è un protocollo di livello applicativo (che usa UDP) che permette a un host di ottenere automaticamente la sua configurazione di rete (indirizzo IP, subnet mask, gateway di default, server DNS) da un server DHCP.

Processo di Assegnazione (DORA)

Il processo di assegnazione di un indirizzo IP tramite DHCP è un dialogo in quattro fasi, noto come DORA:

  1. Discover (Client → Server, Broadcast): L'host appena connesso invia un messaggio DHCPDISCOVER in broadcast per trovare un server DHCP sulla rete.
  2. Offer (Server → Client, Broadcast/Unicast): Uno o più server DHCP sulla rete possono rispondere con un messaggio DHCPOFFER, proponendo un indirizzo IP e altri parametri di configurazione.
  3. Request (Client → Server, Broadcast): L'host sceglie una delle offerte (di solito la prima che riceve) e invia un messaggio DHCPREQUEST in broadcast per accettare formalmente l'offerta e informare tutti i server della sua scelta.
  4. Acknowledge (Server → Client, Broadcast/Unicast): Il server DHCP scelto finalizza l'assegnazione inviando un messaggio DHCPACK, confermando l'indirizzo IP e la durata del "lease" (noleggio).
DHCP Relay Agent: Se un server DHCP deve servire più sottoreti, un DHCP Relay Agent (spesso un router) su ogni sottoreta può inoltrare le richieste DHCP (in unicast) al server centrale.

Cosa Succede se il Server DHCP non Risponde?

Se un client invia un DHCPDISCOVER e non riceve un DHCPOFFER (perché il server è offline, irraggiungibile o ha esaurito gli indirizzi), il client non può ottenere una configurazione di rete. In questo caso, molti sistemi operativi utilizzano APIPA (Automatic Private IP Addressing): l'host si auto-assegna un indirizzo IP nel range 169.254.0.0/16. Questo permette la comunicazione con altri host sulla stessa LAN che si trovano nella stessa situazione, ma non permette la comunicazione con reti esterne.

3. ICMP (Internet Control Message Protocol)

ICMP è un protocollo di supporto a livello di rete (incapsulato direttamente in IP) utilizzato da host e router per inviare messaggi di errore e di controllo relativi al processamento dei pacchetti IP.

Messaggi di Errore Comuni

  • Destination Unreachable: Inviato da un router quando non può inoltrare un pacchetto (es. la rete di destinazione è sconosciuta, il protocollo di trasporto non è attivo, o la frammentazione è necessaria ma il flag DF è impostato).
  • Time Exceeded: Inviato da un router quando il campo TTL (Time To Live) di un pacchetto raggiunge lo zero. Questo previene loop di routing infiniti.
  • Redirect: Inviato da un router a un host sulla stessa rete per informarlo di una rotta migliore verso una destinazione.

Messaggi di Controllo (Query)

  • Echo Request / Echo Reply (Ping): Usato per verificare la raggiungibilità di un host e misurare il Round Trip Time (RTT).
Come funziona Traceroute (Traceroute):
Traceroute è un'utility che usa ICMP per mappare il percorso che un pacchetto segue attraverso la rete.
  1. Invia un pacchetto con TTL=1. Il primo router lo scarta e invia un ICMP "Time Exceeded".
  2. Invia un pacchetto con TTL=2. Il secondo router lo scarta e invia un ICMP "Time Exceeded".
  3. Continua ad incrementare il TTL fino a raggiungere la destinazione.
  4. Per rilevare la destinazione finale, invia un pacchetto UDP a una porta non valida, che risponderà con un ICMP "Destination Unreachable (Port Unreachable)".

4. NAT (Network Address Translation)

NAT è una tecnica utilizzata principalmente per mappare più indirizzi IP privati (usati all'interno di una LAN) in un singolo indirizzo IP pubblico (o un piccolo pool di indirizzi pubblici). È stato introdotto come soluzione temporanea all'esaurimento degli indirizzi IPv4.

Funzionamento di NAT (con Port Mapping - PAT)

Un router NAT al confine della rete privata mantiene una tabella di traduzione.

  • Traffico in Uscita: Quando un host privato (es. 192.168.1.10:1234) invia un pacchetto a un server esterno, il router NAT modifica l'header IP:
    • Sostituisce l'indirizzo IP sorgente privato con il suo indirizzo IP pubblico (es. 88.88.88.88).
    • Sostituisce la porta sorgente originale con una porta pubblica temporanea (es. 54321).
    • Memorizza questa mappatura (192.168.1.10:1234 ↔ 88.88.88.88:54321) nella sua tabella.
  • Traffico in Entrata: Quando il server esterno risponde a 88.88.88.88:54321, il router NAT consulta la sua tabella, trova la mappatura e riscrive l'header del pacchetto con l'indirizzo e la porta privati originali, inoltrandolo all'host corretto.

Implicazioni e Problemi del NAT (Esame ricorrente)

  • Rottura della Connettività End-to-End: Un host esterno non può iniziare una connessione verso un host dietro un NAT, a meno che non sia configurato il port forwarding.
  • Impatto sulle Connessioni TCP: Se l'indirizzo IP pubblico del router NAT cambia nel mezzo di una connessione TCP (come chiesto in un esame), la connessione si interrompe. I pacchetti di risposta dal server verrebbero inviati all'indirizzo IP pubblico vecchio e non raggiungerebbero più il router NAT. L'host mittente andrà in timeout.
  • Firewall "Naturale": NAT agisce come un firewall di base, bloccando le connessioni in entrata non richieste.
  • Necessità di STUN/TURN: Per le comunicazioni peer-to-peer (VoIP, giochi online), sono necessari protocolli come STUN (per scoprire il proprio IP/porta pubblici) e TURN (che agisce come un relay) per attraversare i NAT.
